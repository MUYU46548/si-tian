# refs/ —— 本地参看图库（**只在本机，永不入库**）

> 起因（用户 2026-11-01 原话）：「同样的参考图喂了五六次，现成同类产品的仓库每天挂在 GitHub 等着抄，
> 为什么从来都抄不好？是不是司天要专门搞个临时本地文件夹专门塞参看图？」

成立。这个目录就是那个文件夹。它解决的是**记忆问题**，不是审美问题：

- 参看图原先散在「用户截图 / 方寸日志附件 / `build/ref/` / 下载文件夹 / AI 上下文」五处，
  每次会话结束就失忆 → 下一轮重新要图 → 用户第 N 次重复解释同一件事；
- 现在：**图在这里，口径写在 `MANIFEST.md` 里**，任何 agent 动视觉之前先读清单，不再问第二遍。

## 规则（三条）

1. **只有 `README.md` 与 `MANIFEST.md` 进版本库**，图片/视频/截图/HTML 全部 `.gitignore`。
   理由：参看图多是用户截图或第三方软件画面，含用户数据或版权风险，**禁止提交**。
2. **一张图一条账**：新增图必须同时写进 `MANIFEST.md`（是什么 / 参照哪一层 / 从它身上要抄什么 /
   已经抄到哪一步）。没记账的图 = 不存在，下一轮照样重来。
3. **口径优先于图**：清单里写「从这张图读出的事实」（字号比例、配色、层次），
   agent 抄的是**事实**，不是「感觉像」。

## 目录约定

```
refs/
├── README.md          ← 本文件（入库）
├── MANIFEST.md        ← 参看图清单 + 已吸收/未吸收（入库）
├── src/               ← 原始参看图（不进库）  例：src/20261027-eu4-1518.jpg
├── shots/             ← 用户截图（不进库）    例：shots/20261101-galaxy-shit.png
└── out/               ← 自己的对照产物（不进库，可随时删）
```

## 怎么喂图（给用户的话）

1. 直接说「图我放 `refs/src/` 了，叫 xxx」比在聊天里贴图更耐用 —— 贴图不会留到下一轮，文件会。
2. 顺带一句「这张要抄的是**字号/层次/配色/边界画法**里的哪个」，我按事实抄，不按感觉猜。

## 怎么用图（给 agent 的话）

- 动任何视觉之前：**先读 `MANIFEST.md`**，再看图（`read_image`），最后才动代码。
- 抄完必须回写一行「已吸收：<文件/函数/判据>」；没抄到就写「未吸收 + 原因」。
- 禁止：把参看图当纹理直接贴进产品（版权）、凭印象说「参考了」（没有判据）。
