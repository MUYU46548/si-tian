### 删它们安全吗？—— 两条都查过

1. **对已涂的 `terrainGrid` 无损**：`useTerrainCanvasBrush.resampleInto`（`:176-192`）按**世界坐标**重采样，
   且网格原点恒为 `ax + 整数×cell`（`ax` = 高度图首点）→ 包围盒变化只会让原点**整体平移整数格**，
   逐格无损。⚠️ 旧脚本注释里"原点重推会错位"的担心在现行代码**已不成立**（本次实测确认）。
2. **terrain 清空也安全**：产品本身就有「清空行星地图内容」（`mapDataEditing.clearPlanetContent`，走写闸门 + undo）；
   `terrainBounds` 对空 terrain 回落默认范围（`:89-91`），不会崩。
   且**高度图已是地形主表示**（`terrainRepresentation`：有高度图 → 多边形降为可选叠加物，默认不画）——
   也就是说这 22 个多边形**现在本来就不参与主画面**，只在「地形」叠加图层打开时露出来。

## 四、怎么执行（等你点头）

工具：`scripts/clean-cache-junk.js`（新增 `testpoly` 类别）

```bash
# ① 只看报告，不写盘（默认就是 dry-run）
node scripts/clean-cache-junk.js --only=testpoly

# ② 连退化项之外的都清掉（A 批全部 22 个 —— 因为清空会被守卫拦住，需显式放行）
node scripts/clean-cache-junk.js --only=testpoly --allow-empty

# ③ 确认无误后真正执行：整文件备份到 backups/cleanup-<ts>/ + 被删条目原样存档 archived-removed.json
node scripts/clean-cache-junk.js --only=testpoly --allow-empty --apply
```

- **默认 dry-run**，不加 `--apply` 绝不写盘；
- 写盘前把 `mapdata.json` 整份备份到 `<repo>/backups/cleanup-<ts>/`，被移除的 22 条原样存进 `archived-removed.json`；
- 自检：① 无字段引用；② 清空需显式 `--allow-empty`；③ `--before=<日期>` 可缩窄时间范围。
- ⚠️ **这会写 `E:/图书馆/ROSA`** —— 按你定的"ROSA 只读"红线，**我只跑 dry-run，`--apply` 由你决定**。

### 备选：不删数据，只在界面里"看不见"

若你不想动库缓存，也可以走"**新建项目 → 导入知识库内容 → 在项目里删**"这条路（项目可写、可 undo、库缓存不动）。
代价：只读模式下仍会看到这批旧多边形。
