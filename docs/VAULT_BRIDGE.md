# 读料桥（三刀序列·第二刀）—— 从「只认两个目录」到「整库可读」

> 2026-10-22。对应施工单 `02-司天-三刀序列.md` 任务二。
> 本文回答：读什么、怎么判、缺空间关系怎么办、报告长什么样、**只读**怎么保证。

## 一、它解决什么

旧提取器（`scripts/extract-data.js`）只认两个硬编码目录：

```
03 设定/11 地理系统/      → 地图节点
03 设定/02 场景地点/      → 地图节点
01 索引/地理系统索引.md    → 世界 / 星域
```

后果（真实库 1,353 篇实测）：

- 只有 ~141 篇被读过；人物 / 组织 / 事件 / 物品这些「资料」在司天里没有入口；
- 字段识别是白名单：只认 `层级` / `上层区域` / `地点类型`，换一种写法（`类型`、`类别`、`组织类型`、`书名`…）就读不到；
- 认不出层级时**默认 `location`** —— 事件/人物笔记会被静默变成地点；
- 没有空间关系的笔记不会被报告，用户不知道「哪些没读进去」。

第二刀把这三件事一起改掉：

1. **不挑目录结构**：标准目录存在 → 行为不变；不存在（或显式 `generic`）→ 全库归类扫描；
2. **整份 frontmatter 参与归类**（`scripts/lib/vaultClassify.js`，纯函数）；
3. **识别不了的每条都进报告**（路径 + 为什么 + 凭据），并落到设置面板「待人工」；
4. **空间关系逐级推断**（显式字段 → 正文双链 → 正文句式），推断的标 `inferred`，
   找不到的进待人工，**不造名字、不硬塞父级**。

## 二、归类口径（单源：`scripts/lib/vaultClassify.js`）

| 类目 | 含义 | 典型信号 |
|---|---|---|
| `geo` | 地图实体（会变成节点） | `层级: 城市`、tags `[地理系统]`、目录 `03 设定/11 地理系统`、文件名后缀 `…港/…城` |
| `character` | 人物 | `类型: 主要角色`、tags `[人物]`、目录 `03 设定/01 人物` |
| `organization` | 组织 | `组织类型`、tags `[组织]`、目录 `06 组织势力` |
| `item` | 物品装备 | `归属大类`、`类别: 遗物`、tags `[物品装备]` |
| `creature` | 种族/生物 | tags `[种族/生物/怪物]`、目录 `08 种族` |
| `event` | 历史事件 | `层级: 事件`、目录 `03 历史事件` |
| `concept` | 概念/规则 | tags `[基础设定/军事/魔法管制]` |
| `document` | 作品/文档 | `书名` + `章节编号`、目录 `04 官方作品` |
| `reference` | 资料收藏 | 目录 `07 资料收藏` |
| `meta` | 模板/维护/说明 | 目录 `99 模板`、`96 事务管理`、`_` 前缀 |
| `index` | 索引 | 目录 `01 索引` |
| `unknown` | **待人工** | 以上都没有 |

判定顺序（**结构优先级**故意排在 frontmatter 前面）：

```
结构目录（模板/索引/事务/资料收藏） → `_` 前缀 → 显式层级 → 类目键（组织类型/书名…）
→ 类型值（主要角色/遗物…）→ 类目目录 → 标签 → 路径层级词 → 文件名后缀 → unknown
```

> `99 模板/世界模板.md` 里写着 `层级: 世界`，那是模板示例 —— 结构目录优先，判 `meta`。
> 这条有单测（`unit/test_vault_classify.js` 第二条）。

## 三、空间关系：三档，且推断必须可辨认

给每个 `geo` 条目找上层：

1. **显式字段**（`上层区域` / `上级页面` / `上级` / `parent` / `属于` / `位于`…）→ `inferred: false`；
   - 值是 `无` / `-` → 当作「明确没有」，继续往下试；
   - 指向一个**库里不存在**的词条 → 进待人工并点名（`parent-missing`），不静默丢。
2. **正文双链**：第一个能解析到 geo 条目的 `[[…]]` → `inferred: true, signal: wikilink`；
3. **正文句式**：`位于/坐落于/地处/处于/属于/隶属` + **已知实体名**（后面必须跟
   `的/境内/附近/一带/标点` 等边界词）→ `inferred: true, signal: text`；
4. 都没有 → `needsHuman: 'spatial'`（列表里写「没有任何上层线索」）。

另外，`extract-data.js` 里原有的「缺父级时拿第一个 wikilink 当父级」也补上了标记：
节点上写 `parentInferred: true` + `parentSource: 'wikilink'`，导出/界面不得当成用户写的上层。

## 四、报告（零静默丢失）

`classifyReport(index)` 返回：

```js
{
  total,                  // 索引里的全部条目
  byCategory: {...},      // 每个条目**恰好**落一个类目（Σ = total，单测守恒）
  byLayer: {...},         // geo 按粒度
  geo: [...],             // 地图实体（含 parentTitle / parentInferred / evidence）
  needsHuman: [...],      // 每一条：path / title / category / reasons / evidence
  inferred: [...],        // 推断出来的上层（谁、依据、原文片段）
}
```

`needsHuman` 的三种 `category`：

- `unknown`：没有任何分类信号（`reasons: 没有任何可用的分类信号`）；
- `geo` + `layer`：认得出是地点，认不出粒度；
- `geo` + `spatial` / `parent-missing`：找不到上层 / 上层指向不存在的词条。

## 六点五、用户乱写怎么办（2026-10-22 补强）

用户提醒原话：「真实场景中用户的 frontmatter 可能随便乱写……甚至可能不按标准格式来，或者混了一堆插件产物。」
所以读料层不做「规范假设」，只做「不崩、不丢、能救就救」：

| 脏写法 | 处理 |
|---|---|
| `层级:　城市`（冒号后全角空格） | YAML 会把整行当键名 → `normalizeFrontmatter` 按行抢救 |
| `层级：城市`（全角冒号）/ `层级 = 城市`（TOML 风） | 同上（`:` `：` `=` 三种分隔符） |
| `层级: "[[城镇]]"` / `类型: '主要角色'` | 值规范化：去 `[[ ]]`、去首尾引号、去全角空白后再比对 |
| `tags: "#地点 #港口"` / `tags: a b` | `asTagList` 按空白/逗号/# 拆开（别名不拆 —— 别名可以含空格） |
| `tags: {primary: 地点}` / `tags: 114514` | 不崩；拿不到就靠其它信号，最后进待人工 |
| 缺少闭合 `---` | 当作没有 frontmatter → 按目录/文件名归类，仍进报告 |
| YAML 语法错（`层级: [城市`） | 条目保留、`parseError` 记录下来，待人工原因写「frontmatter 解析失败」 |
| BOM / 正文 dataview `key:: value` | BOM 剥掉；dataview 不是 frontmatter，不参与归类 |
| 插件键（`cssclasses` / `banner` / `dg-publish` / `dataview`） | 一律忽略，不影响归类 |
| 上层的三种写法 `[[北境|北]]` / `北境` / `无` | 前两种解析到目标；「无」= 明确没有上层（不误报断链） |

判据：`scripts/tests/unit/test_vault_frontmatter_noise.js`（7 组，16 篇全是脏数据；
包括「总数守恒：报告条目 = 笔记数，一个都不吞」）。

## 七点五、设定卡读不到笔记时（2026-10-24）

节点面板的设定卡（frontmatter + 正文 + 关联资料）吃的是 `sourcePath`。**换库 / 笔记改名 / 删除**之后
这个路径会指向不存在的文件 —— 以前只是 `note = null`，正文区静默消失，用户以为"内容没了"。

现在给**可读回落**（`[data-testid="lore-missing"]`）：

- 点名来源路径 + 主进程返回的真实原因（如 `ENOENT: ...`）；
- 两个出口：**重试**（重新读这篇）/ **全库搜「节点名」**（打开资料搜索并带上关键词、直接搜）；
- 明确写着"归属与坐标仍以项目文件为准"（读料失败不影响项目数据，也不写任何东西）；
- 读取只走 `readObsidianNote`（**只读**；回落块里没有任何写 IPC —— test_141 读源码守）。

顺带修一处真隐患：`updateNode` 是**就地改对象**，`watch(node)` 看不到引用变化 ——
同一节点换了 `sourcePath` 后正文会停在旧内容上。加了 `watch(() => node.sourcePath)` 之后才真正重读。

## 七点六、新建笔记落在哪 + 写什么 frontmatter（2026-10-24 用户拍板：选项 B）

唯一实现：`src/main/noteTarget.js`（纯 Node，可被单测直接跑）+ `create-obsidian-note` / 批量导入两个写口。

**落点**（`resolveNoteTarget`）：

| 顺序 | 条件 | 落点 |
|---|---|---|
| ① | 调用方显式给了 `targetDir` | 用它（库内相对或绝对；将来加"新笔记目录"设置项就走这里） |
| ② | 库里**有** `03 设定` | `03 设定/11 地理系统/{星域,星系,行星}`；其它层级 → `03 设定/02 场景地点`（子目录自动建） |
| ③ | 库里**没有** `03 设定` | **库根目录**，并回 `usedRootFallback: true` |

⚠️ 判据是"`03 设定` 存在"，不是"子目录存在"：以前无条件 `mkdir -p`，在一个没有这套目录的库里转正
一个节点，会**替用户造一棵 `03 设定/11 地理系统/...`**（等于改人家的库结构）。批量导入同一口径。

**frontmatter**（`buildNoteFrontmatter`，选项 B）：只写

- `层级`：中文标签（`galaxy → 星系`、`city → 城市`…；未知层级原样写，不编造）
- `上层区域`：`[[父节点名字]]`（**名字优先**；只有 id 时用 id 兜底 —— wikilink 要能解析到真笔记）
- `tags`：非空才写

**绝不写 `coordinate`**（AGENTS 红线：坐标是编辑器元数据）；也不再写英文 `layer` 键。

判据：`scripts/tests/unit/test_note_target.js`（6 组）—— 显式目录 / 约定目录（子目录不必先存在）/
根目录兜底（且裸库没被造出 `03 设定`）/ frontmatter 三键（英文 layer 与 coordinate 都不出现）/
真实文件系统上真 mkdir+写文件 / 源码守卫（handler 用的是这两个函数，create 段零 coordinate）。

## 八、明确没做

- **不做自动导入**：候选仍需人确认（原来的 D2 边界不变）；本刀只把「读得到」做扎实。
- **不用 LLM 猜**：归类是规则 + 证据，宁可 `unknown`。
- 全文语义检索 / 向量化：不在本刀。
