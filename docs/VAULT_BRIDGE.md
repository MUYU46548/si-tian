# 读料桥（三刀序列·第二刀）—— 从「只认两个目录」到「整库可读」

> 2026-10-22。对应施工单 `02-司天-三刀序列.md` 任务二。
> 本文回答：读什么、怎么判、缺空间关系怎么办、报告长什么样、**只读**怎么保证。

## 一、它解决什么

旧提取器（`scripts/extract-data.js`）只认两个硬编码目录：

```
03 设定/11 地理系统/      → 地图节点
03 设定/02 场景地点/      → 地图节点
01 索引/地理系统索引.md    → 世界 / 星域
```

后果（真实库 1,353 篇实测）：

- 只有 ~141 篇被读过；人物 / 组织 / 事件 / 物品这些「资料」在司天里没有入口；
- 字段识别是白名单：只认 `层级` / `上层区域` / `地点类型`，换一种写法（`类型`、`类别`、`组织类型`、`书名`…）就读不到；
- 认不出层级时**默认 `location`** —— 事件/人物笔记会被静默变成地点；
- 没有空间关系的笔记不会被报告，用户不知道「哪些没读进去」。

第二刀把这三件事一起改掉：

1. **不挑目录结构**：标准目录存在 → 行为不变；不存在（或显式 `generic`）→ 全库归类扫描；
2. **整份 frontmatter 参与归类**（`scripts/lib/vaultClassify.js`，纯函数）；
3. **识别不了的每条都进报告**（路径 + 为什么 + 凭据），并落到设置面板「待人工」；
4. **空间关系逐级推断**（显式字段 → 正文双链 → 正文句式），推断的标 `inferred`，
   找不到的进待人工，**不造名字、不硬塞父级**。

## 二、归类口径（单源：`scripts/lib/vaultClassify.js`）

| 类目 | 含义 | 典型信号 |
|---|---|---|
| `geo` | 地图实体（会变成节点） | `层级: 城市`、tags `[地理系统]`、目录 `03 设定/11 地理系统`、文件名后缀 `…港/…城` |
| `character` | 人物 | `类型: 主要角色`、tags `[人物]`、目录 `03 设定/01 人物` |
| `organization` | 组织 | `组织类型`、tags `[组织]`、目录 `06 组织势力` |
| `item` | 物品装备 | `归属大类`、`类别: 遗物`、tags `[物品装备]` |
| `creature` | 种族/生物 | tags `[种族/生物/怪物]`、目录 `08 种族` |
| `event` | 历史事件 | `层级: 事件`、目录 `03 历史事件` |
| `concept` | 概念/规则 | tags `[基础设定/军事/魔法管制]` |
| `document` | 作品/文档 | `书名` + `章节编号`、目录 `04 官方作品` |
| `reference` | 资料收藏 | 目录 `07 资料收藏` |
| `meta` | 模板/维护/说明 | 目录 `99 模板`、`96 事务管理`、`_` 前缀 |
| `index` | 索引 | 目录 `01 索引` |
| `unknown` | **待人工** | 以上都没有 |

判定顺序（**结构优先级**故意排在 frontmatter 前面）：

```
结构目录（模板/索引/事务/资料收藏） → `_` 前缀 → 显式层级 → 类目键（组织类型/书名…）
→ 类型值（主要角色/遗物…）→ 类目目录 → 标签 → 路径层级词 → 文件名后缀 → unknown
```

> `99 模板/世界模板.md` 里写着 `层级: 世界`，那是模板示例 —— 结构目录优先，判 `meta`。
> 这条有单测（`unit/test_vault_classify.js` 第二条）。

## 三、空间关系：三档，且推断必须可辨认

给每个 `geo` 条目找上层：

1. **显式字段**（`上层区域` / `上级页面` / `上级` / `parent` / `属于` / `位于`…）→ `inferred: false`；
   - 值是 `无` / `-` → 当作「明确没有」，继续往下试；
   - 指向一个**库里不存在**的词条 → 进待人工并点名（`parent-missing`），不静默丢。
2. **正文双链**：第一个能解析到 geo 条目的 `[[…]]` → `inferred: true, signal: wikilink`；
3. **正文句式**：`位于/坐落于/地处/处于/属于/隶属` + **已知实体名**（后面必须跟
   `的/境内/附近/一带/标点` 等边界词）→ `inferred: true, signal: text`；
4. 都没有 → `needsHuman: 'spatial'`（列表里写「没有任何上层线索」）。

另外，`extract-data.js` 里原有的「缺父级时拿第一个 wikilink 当父级」也补上了标记：
节点上写 `parentInferred: true` + `parentSource: 'wikilink'`，导出/界面不得当成用户写的上层。

## 四、报告（零静默丢失）

`classifyReport(index)` 返回：

```js
{
  total,                  // 索引里的全部条目
  byCategory: {...},      // 每个条目**恰好**落一个类目（Σ = total，单测守恒）
  byLayer: {...},         // geo 按粒度
  geo: [...],             // 地图实体（含 parentTitle / parentInferred / evidence）
  needsHuman: [...],      // 每一条：path / title / category / reasons / evidence
  inferred: [...],        // 推断出来的上层（谁、依据、原文片段）
}
```

`needsHuman` 的三种 `category`：

- `unknown`：没有任何分类信号（`reasons: 没有任何可用的分类信号`）；
- `geo` + `layer`：认得出是地点，认不出粒度；
- `geo` + `spatial` / `parent-missing`：找不到上层 / 上层指向不存在的词条。

## 五、怎么用

### 命令行（只读，推荐先跑这个）

```bash
node scripts/vault-scan.mjs --vault "E:\图书馆\ROSA" --out "$env:TEMP\rosetta-scan" --geodata
```

产物（全在 `--out` 下，**不在库里**）：

- `scan-report.json`：全量报告 + 提取报告（跳过/推断/重名/待人工）；
- `待人工.md`：给人看的清单，每条 `路径 — 为什么｜依据`；
- `geodata.json`：可当作提取结果加载的节点表（试导）。

只读保证：`buildIndex(..., {write:false})`、`extractGeodata(..., {writeCache:false})`，
输出目录在库内直接拒绝；跑完对库做一次指纹对比（全部 md 的 size+mtime、`.sitian` 内文件），
输出 `只读校验：✅ 库内文件与 .sitian 均未改动`。

### 应用内

设置 → 资料索引：重建后显示

```
候选地图实体：N   高置信 M   地图 140 / 资料 1188 / 待人工 35（推断 4）   [查看候选] [待人工]
```

点「待人工」逐条看原因。归类与推断在**主进程**完成（`vault-classify-report` IPC），
渲染层只展示，不读盘。

## 八、明确没做

- **不做自动导入**：候选仍需人确认（原来的 D2 边界不变）；本刀只把「读得到」做扎实。
- **不用 LLM 猜**：归类是规则 + 证据，宁可 `unknown`。
- 全文语义检索 / 向量化：不在本刀。
