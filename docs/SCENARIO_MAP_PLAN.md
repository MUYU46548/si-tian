# SiTian 剧本地图（Timeline Scenario Map）开发规划

> 基准日：2026-09-08 ｜ 依据：用户需求（欧陆风云4 式历史剧本地图）+ 代码实测 + ROSA 数据实测
> 用户原始需求：特殊剧本地图，按不同历史时期呈现不同地图（类 EU4 历史剧本）。非全局添加，仅部分场景使用，可含已不存在的地点（不需要在大地图直接体现）。可能需要单独的地图模式。

## 0. 数据实测结论（决定架构的关键事实）

### ROSA 侧已具备的时间资产

| 资产 | 位置 | 内容 |
|:---|:---|:---|
| **七时代划分** | `06 年表/幻境基础年表.md` | 第Ⅰ黑暗（2006-2008）→ 第Ⅱ帝国（2008-2014）→ 第Ⅲ复仇（2014-2018）→ 第Ⅳ觉醒（2018-2020.4）→ 第Ⅴ神话（2020.4-2023.2）→ 第Ⅵ光辉（2023.2-2024.2）→ 第Ⅶ星河（2024.2-今） |
| **主时间基准** | 年表索引.md | 幻境基础年表为主年表，乐园星时间（乐园星历）为标准时间体系 |
| **四条分支年表** | `06 年表/` | 月兔线/魔女线/粘土世界线/幻境基础——多世界各自纪年（粘土=青崖2049） |
| **16 篇历史事件** | `03 设定/03 历史事件/` | 正文含纪年（如"青崖2049年"），frontmatter **无结构化年份字段** |
| **时间钟楼词条** | `02 场景地点/05 柯依尔世界/` | 世界观内时间装置（可作时间切换的叙事锚点） |

### 现状缺口

- 历史事件的纪年只存在于正文散文里（"青崖2049年"），**无 frontmatter 结构化字段** → 机器不可读
- `06 年表/` 目录完全不在提取范围内（extract-data.js 只扫 `03 设定/11 地理系统` 和 `02 场景地点`）→ 时代划分对司天不可见
- 年表正文明确"不建议使用内部链接"（防链接爆炸）→ 不能指望从年表反向解析出"时代↔地点"映射

## 1. 需求拆解（从用户描述提取的 4 条硬需求）

1. **剧本 = 时代切片**：同一地理位置在不同历史时期有不同的归属/名称/存在状态（EU4 剧本本质）
2. **非全局**：只有部分场景/行星需要剧本，其他地图保持现状（无时代概念）——不能强迫所有地图都有 era 维度
3. **可含已消失地点**：某时代存在的地点在"现在"的大地图上不存在（不占当前位置）——这是与"当前地图"最大的数据结构分歧
4. **独立地图模式**：用户自己判断需要一个单独的模式，而不是在现有 PlanetMap 上叠加开关

## 2. 架构决策：三种方案的取舍

### 方案 A：era 维度横切过滤（store 注释里的预留方案 2）

给每个节点/地形打 era 标签，顶栏切换时代 → 过滤渲染。

- **优点**：数据一体，无重复地图
- **致命伤**：违反硬需求 2——所有地图被迫携带 era 维度；违反硬需求 3——已消失地点必须存在于当前数据集（污染大地图、树导航、搜索、自动区域生成全部要加 era 过滤，侵入 22 个 composables）
- **结论：否决**（仅适合"轻量时间筛选"的次要场景，不是用户要的剧本）

### 方案 B：独立剧本数据文件（ScenarioMap，推荐）

新增**与 mapData 平行**的 `scenarioData[scenarioId]` 命名空间，每个剧本一张自包含地图。

- **优点**：
  - 零侵入现有链路：PlanetMap/GalaxyMap/搜索/树导航/自动区域完全不感知剧本
  - 天然满足"非全局"：剧本挂在某个行星/星域下按需创建，没有剧本的地图完全不变
  - 满足"已消失地点"：剧本地图内可自由画"前朝旧都"，当前大地图上根本没有这个节点
  - 复用现有渲染器：useCanvasRenderer/planetDrawing 的绘制管线按数据源注入即可复用（Stellaris 风格地图的本质是数据驱动渲染）
- **代价**：需要抽象"地图数据源"接口（terrain/regions/markers/places 的读写路径从 mapData[planetId] 换成 scenarioData[key]），PlanetMap 模板/交互可复制改造
- **结论：采用**

### 方案 C：场景级微剧本（scene 视图，store 注释预留方案 3）

把剧本做成"地点特写"的更深一层。

- **结论：不满足**——用户要的是 EU4 式**宏观区域地图**（行星级/星域级的历史疆域变迁），不是单个场景特写。但 C 可作为 B 的后续扩展（剧本地图内再下钻）。

## 3. 数据模型设计（草案）

### 3.1 存储层

```
.sitian/scenarios.json          # 新文件，与 geodata.json/mapdata.json 平行
{
  "version": 1,
  "scenarios": {
    "<scenarioId>": {           # scenarioId = `${ownerMapKey}/${scenarioSlug}`
      "id": "幻境/乐园星/第一时代",
      "ownerKey": "幻境/乐园星",      # 挂载在哪个地图（mapDataKey）
      "name": "第一时代·黑暗时代",
      "era": { "roman": "Ⅰ", "label": "黑暗时代", "startYear": "乐园星历2006", "endYear": "乐园星历2008" },
      "description": "...",           # 可选：剧本说明（可链接 Obsidian 词条）
      "sourceNote": "",               # 可选：关联 Obsidian 年表/事件词条路径
      "data": {                       # 与 mapData 同构，自包含
        "terrain": [...], "regions": [...], "markers": [...],
        "routes": [...], "textLabels": [...], "clusters": [...],
        "places": [...]               # ⚠️ 剧本私有节点（已消失地点在这里）
      },
      "inheritBase": true,            # 是否以当前地图为底稿（拷贝起点）
      "createdAt": "...", "updatedAt": "..."
    }
  }
}
```

**关键设计**：
- `places` 进剧本数据：已消失地点 = 剧本私有 draft 节点（`draft: true`，无 Obsidian 词条，`sourcePath: ''`），与现有暂存地点机制同构——**符合"只创建不修改"铁律**，剧本节点不回写 Markdown
- `inheritBase: true` 的剧本创建时深拷贝当前地图 → "从现状改起"符合历史剧本工作流（先有现代地图，倒推历史）
- 时代字段（era）存 roman/label/年份区间，**直接对齐年表索引的七时代表述**；但不做强校验（自由文本，防世界观看不见的剧本被格式卡住）

### 3.2 Obsidian 侧约定（写入 SITIAN_VAULT_SPEC 新章节）

给历史事件词条推荐**可选** frontmatter 字段（渐进增强原则）：

```yaml
---
年份: 青崖2049年        # 自由文本纪年
时期: 第Ⅱ时代           # 可选，罗马数字或名称，对齐年表
关联剧本: 第一时代       # 可选，指向剧本名
---
```

提取端（extract-data.js）**本阶段不解析这些字段**——剧本地图的手工属性远多于机器推断，第一版纯手动创建剧本即可。字段规范先立，解析后置。

## 4. 分阶段开发计划（P0 → P3）

### P0 — 数据层 + 最小剧本地图（~2 天）

1. `scenarioData` ref + CRUD 模块（`store/geodataModules/scenarioEditing.js`）：
   - createScenario（inheritBase 深拷贝 / 空白起步）、updateScenario、removeScenario、listScenarios(ownerKey)
   - 全部走 undo（复用 execute，红线 8：redo 唯一写入点）
   - saveGeodata 保存对称性（铁律：新增 ref 必进 saveGeodata，防刷新即丢）
2. 主进程 IPC：load/save scenarios.json（带损坏容错：JSON.parse 失败回退空对象 + 提示，不崩溃）
3. **ScenarioMap.vue（最小版）**：复制 PlanetMap.vue 骨架，数据源指向 scenario.data——先只支持：地形绘制、聚落放置（draft 节点）、标记、平移缩放。不要一次搬 22 个 composables
4. 入口：行星地图工具栏加"⏳ 剧本"按钮 → 剧本列表面板（新建/进入/删除）
5. 验收：创建"第Ⅶ时代"剧本（inheritBase）→ 画一块"旧王国疆域"地形 → 切回当前地图零变化 → 重启后剧本仍在

### P1 — 时代切换与剧本管理（~1 天）

1. 剧本列表升级：按 era.roman 排序的时间轴条（Ⅰ→Ⅶ 横排按钮），一键切换剧本/回当前
2. 剧本间差异可视化（可选）：切换时代时地形差异高亮（新增=金色描边，消失=灰色虚影）——历史剧本职心体验
3. 剧本元数据编辑：名称/时代区间/说明/关联 Obsidian 词条（readObsidianNote 复用现有 IPC）
4. NodeDetailPanel 适配：剧本节点的详情面板隐藏"创建 Obsidian 笔记"以外的写操作（剧本节点默认全 draft，不强制转正）

### P2 — 与大地图的弱关联（~1 天）

1. 当前地图上显示"剧本锚点"：有剧本的行星在 GalaxyMap/PlanetMap 显示小沙漏角标（不进入大地图数据）
2. 剧本词条跳转：NodeDetailPanel 若节点 frontmatter 有 `关联剧本`，显示"⏳ 查看历史剧本"按钮直达
3. 导出：剧本地图 PNG 导出带时代标注水印（复用 useFullMapExport，标题行加 era label）

### P3 — 打磨与远期

1. 剧本模板：空白/从当前拷贝/仅边界（只画疆域轮廓）
2. 时代图例：剧本地图自动汇总"该时代存在的势力/地点"图例（复用 U7 图例规划）
3. 多剧本对比视图（远期，暂不做）：同屏两个时代并排
4. GeoJSON 导入导出支持 scenario.data（E10 链路顺带）

## 5. 红线与陷阱（执行时必读）

1. **禁止 era 过滤侵入现有链路**：ScenarioMap 是平行数据源，任何"在 PlanetMap 里按时代过滤"的方案都会重蹈方案 A 覆辙
2. **undo 双写陷阱**：scenarioEditing 全部走 execute，redo 内完成首次写入
3. **保存对称性**：scenarioData 必须进 saveGeodata/备份（.sitian/scenarios.json 单独文件则备份钩子要覆盖它）
4. **Ref 壳陷阱（#54）**：新 composable（useScenarioEditor）从第一天就顶层解构，模板禁止 `scenarioEditor.xxx` 嵌套引用——本会话簇弹窗锁死的教训
5. **剧本节点不回写 Markdown**：draft 机制，与"坐标不回写"同级铁律
6. **mapDataKey 隔离**：scenarioId 含 ownerKey（`幻境/乐园星/xx`），复用 getMapDataKey 的 world 前缀逻辑，防跨世界同名碰撞
7. **新视图层级五处同步**：若剧本作为独立 viewLevel（`scenario`），按红线 11 同步 App.vue 路由/面包屑/backTo*/layers.js/geodata select*

## 6. 与既有规划的合并

- store 注释预留点 2（timeline 横切过滤）：本规划落地后，注释更新为指向本文件——横切过滤降级为 P3 可选（适合"给当前地图按时代隐藏部分节点"的轻需求，与剧本地图并存）
- briefing P2.3 罗马数字排序：无关，不合并
- U7 图例：P3 剧本图例复用其规划，不合并

## 7. 待用户确认的分叉点

1. 剧本粒度：第一版只做**行星级**（挂行星下）还是连星域级一起？——建议 P0 只做行星级（对齐 PlanetMap 复用），星域级 P2 再说
2. 时代数据来源：手动填 era 字段（推荐第一版）vs 解析年表 md 自动生成（P2+，需要 06 年表进提取范围——建议先手动，自动解析易受年表散文格式干扰）
3. "已消失地点"是否需要出现在树导航/搜索里？——建议默认不出现（剧本自包含），P2 给搜索加"含剧本"开关
