## 1. 需求拆解（从用户描述提取的 4 条硬需求）

1. **剧本 = 时代切片**：同一地理位置在不同历史时期有不同的归属/名称/存在状态（EU4 剧本本质）
2. **非全局**：只有部分场景/行星需要剧本，其他地图保持现状（无时代概念）——不能强迫所有地图都有 era 维度
3. **可含已消失地点**：某时代存在的地点在"现在"的大地图上不存在（不占当前位置）——这是与"当前地图"最大的数据结构分歧
4. **独立地图模式**：用户自己判断需要一个单独的模式，而不是在现有 PlanetMap 上叠加开关 → 已细化（§7 决策 2）：单独入口 + 全屏模式层，不与常规导航混编

## 2. 架构决策：三种方案的取舍

### 方案 A：era 维度横切过滤（store 注释里的预留方案 2）

给每个节点/地形打 era 标签，顶栏切换时代 → 过滤渲染。

- **优点**：数据一体，无重复地图
- **致命伤**：违反硬需求 2——所有地图被迫携带 era 维度；违反硬需求 3——已消失地点必须存在于当前数据集（污染大地图、树导航、搜索、自动区域生成全部要加 era 过滤，侵入 22 个 composables）
- **结论：否决**（仅适合"轻量时间筛选"的次要场景，不是用户要的剧本）

### 方案 B：独立剧本数据文件（ScenarioMap，推荐）

新增**与 mapData 平行**的 `scenarioData[scenarioId]` 命名空间，每个剧本一张自包含地图。

- **优点**：
  - 零侵入现有链路：PlanetMap/GalaxyMap/搜索/树导航/自动区域完全不感知剧本
  - 天然满足"非全局"：剧本挂在某个行星下按需创建，没有剧本的地图完全不变
  - 满足"已消失地点"：剧本地图内可自由画"前朝旧都"，当前大地图上根本没有这个节点
  - 复用现有渲染器：useCanvasRenderer/planetDrawing 的绘制管线按数据源注入即可复用（Stellaris 风格地图的本质是数据驱动渲染）
- **代价**：需要抽象"地图数据源"接口（terrain/regions/markers/places 的读写路径从 mapData[planetId] 换成 scenarioData[key]），PlanetMap 模板/交互可复制改造
- **结论：采用**

### 方案 C：场景级微剧本（scene 视图，store 注释预留方案 3）

把剧本做成"地点特写"的更深一层。

- **结论：不满足**——用户要的是 EU4 式**宏观区域地图**（行星级的历史疆域变迁），不是单个场景特写。但 C 可作为 B 的后续扩展（剧本地图内再下钻）。

## 3. 数据模型设计（草案）

> ⚠️ **2026-09-08 二次修订**：`scenario.data` 的实际形状以 **§8 核心模型为准**（`polities[]` 染色多边形 + `labels[]` 历史地名 + `markers[]` 可选标记，底图共享只读）。本节 `places` draft 节点 / `inheritBase` 深拷贝整图为旧稿保留作背景——真实用例（单行星势力染色）下剧本不改地形、不做 draft 节点。

### 3.1 存储层

```
.sitian/scenarios.json          # 新文件，与 geodata.json/mapdata.json 平行；剧本信息唯一落点
{
  "version": 1,
  "scenarios": {
    "<scenarioId>": {           # scenarioId = `${ownerMapKey}/${scenarioSlug}`
      "id": "幻境/乐园星/第一时代",
      "ownerKey": "幻境/乐园星",      # 挂载在哪个地图（mapDataKey，行星级=行星 mapDataKey）
      "name": "第一时代·黑暗时代",
      "era": { "roman": "Ⅰ", "label": "黑暗时代", "startYear": "乐园星历2006", "endYear": "乐园星历2008" },
      "order": 1,                     # 手动排序权重（P1 时间轴条按此排，不解析 roman）
      "description": "...",           # 可选：剧本说明
      "sourceNote": "",               # 可选：手动填写的 Obsidian 词条路径，只读引用，永不回写
      "data": {                       # 与 mapData 同构，自包含
        "terrain": [...], "regions": [...], "markers": [...],
        "routes": [...], "textLabels": [...], "clusters": [...],
        "places": [...]               # ⚠️ 剧本私有节点（已消失地点在这里）
      },
      "inheritBase": true,            # 是否以当前地图为底稿（拷贝起点）
      "createdAt": "...", "updatedAt": "..."
    }
  }
}
```

**关键设计**：
- `places` 进剧本数据：已消失地点 = 剧本私有 draft 节点（`draft: true`，无 Obsidian 词条，`sourcePath: ''`），与现有暂存地点机制同构——**符合"只创建不修改"铁律**，剧本节点不回写 Markdown
- **已消失地点默认不进大地图/树导航/搜索（剧本自包含）**；后续给搜索加「含剧本」开关（P2，§7 决策 4）
- `inheritBase: true` 的剧本创建时深拷贝当前地图 → "从现状改起"符合历史剧本工作流（先有现代地图，倒推历史）
- **era 全部手动填写**（roman/label/年份区间均为自由文本），不做年表自动划分/识别（年表散文格式机器粗略识别几乎必错，§7 决策 3）；剧本排序用手动 `order`，roman 仅作展示
- 剧本信息唯一落点 = `.sitian/scenarios.json`，**不回写 Obsidian**（设定库没有它们的位置，§3.2 已取消）

### 3.2 Obsidian 侧约定（已取消，2026-09-08）

无任何 Obsidian 侧约定。用户确认：剧本相关信息不写回 Obsidian（设定库没有它们的位置），纯司天地图文件。原"给历史事件词条推荐 年份/时期/关联剧本 可选 frontmatter 字段"的渐进增强方案**作废**——不修改任何既有词条，不新增字段规范；`sourceNote` 仅为司天侧手动填写的只读引用。

## 4. 分阶段开发计划（P0 → P3）

### P0 — 数据层 + 最小剧本地图（~2 天）

1. `scenarioData` ref + CRUD 模块（`store/geodataModules/scenarioEditing.js`）：
   - createScenario（inheritBase 深拷贝 / 空白起步）、updateScenario、removeScenario、listScenarios(ownerKey)
   - 全部走 undo（复用 execute，红线 26：redo 唯一写入点）
   - saveGeodata 保存对称性（铁律：新增 ref 必进 saveGeodata，防刷新即丢）
2. 主进程 IPC：load/save scenarios.json（带损坏容错：JSON.parse 失败回退空对象 + 提示，不崩溃）
3. **ScenarioMap.vue（最小版）**：复制 PlanetMap.vue 骨架，数据源指向 scenario.data——先只支持：地形绘制、聚落放置（draft 节点）、标记、平移缩放。不要一次搬 22 个 composables
4. **入口（单独入口原则，§7 决策 2）**：行星地图工具栏加「⏳ 剧本」按钮 → 剧本列表面板（新建/进入/删除）；剧本地图以**全屏模式层**呈现（挂于 PlanetMap 之上），**不注册 viewLevel**——面包屑/树导航/搜索/路由零改动
5. 验收：创建"第Ⅶ时代"剧本（inheritBase）→ 画一块"旧王国疆域"地形 → 切回当前地图零变化 → 重启后剧本仍在；且面包屑/树导航/搜索全程无剧本痕迹

### P1 — 时代切换与剧本管理（~1 天）

1. 剧本列表升级：按 `order` 排序的时间轴条（Ⅰ→Ⅶ 横排按钮），一键切换剧本/回当前
2. 剧本间差异可视化（可选）：切换时代时地形差异高亮（新增=金色描边，消失=灰色虚影）——历史剧本核心体验
3. 剧本元数据编辑：名称/时代区间（手动自由文本）/说明/sourceNote（可选，手动填 Obsidian 词条路径，只读引用）

### P2 — 与大地图的弱关联（~1 天）

1. 当前地图上显示"剧本锚点"：有剧本的行星在 GalaxyMap/PlanetMap 显示小沙漏角标（不进入大地图数据）
2. 搜索开关：搜索面板加「含剧本地点」选项（默认关——已消失地点默认不进搜索，§7 决策 4 的正式出口）
3. 导出：剧本地图 PNG 导出带时代标注水印（复用 useFullMapExport，标题行加 era label）

### P3 — 打磨与远期

1. 剧本模板：空白/从当前拷贝/仅边界（只画疆域轮廓）
2. 时代图例：剧本地图自动汇总"该时代存在的势力/地点"图例（复用 U7 图例规划）
3. 多剧本对比视图（远期，暂不做）：同屏两个时代并排
4. GeoJSON 导入导出支持 scenario.data（E10 链路顺带）

## 5. 红线与陷阱（执行时必读）

1. **禁止 era 过滤侵入现有链路**：ScenarioMap 是平行数据源，任何"在 PlanetMap 里按时代过滤"的方案都会重蹈方案 A 覆辙
2. **undo 双写陷阱**：scenarioEditing 全部走 execute，redo 内完成首次写入
3. **保存对称性**：scenarioData 必须进 saveGeodata/备份（.sitian/scenarios.json 单独文件则备份钩子要覆盖它）
4. **Ref 壳陷阱（#54）**：新 composable（useScenarioEditor）从第一天就顶层解构，模板禁止 `scenarioEditor.xxx` 嵌套引用——本会话簇弹窗锁死的教训
5. **剧本数据零回写 Obsidian**：scenarios.json 是剧本信息唯一落点；不修改任何 Obsidian 词条（含 frontmatter，§3.2 已取消），剧本节点保持 draft 机制——与"坐标不回写"同级铁律
6. **mapDataKey 隔离**：scenarioId 含 ownerKey（`幻境/乐园星/xx`），复用 getMapDataKey 的 world 前缀逻辑，防跨世界同名碰撞
7. **剧本不是 viewLevel**：全屏模式层挂载于 PlanetMap 之上，App.vue 面包屑/路由、backTo* 清理链、layers.js 零改动，「新视图层级五处同步」（开发陷阱 #25）不适用；但**退出剧本模式必须完整恢复** PlanetMap 数据源、图层面板与交互状态

### 核心模型（三次修订后，取代 §3 旧稿与二次修订稿）

```
.sitian/scenarios.json（唯一落点，扩展为两段）
{
  "version": 2,
  "baseMaps": {                       # 独立底图，与 Obsidian 完全无关
    "德斯特星": {
      "id": "德斯特星",
      "name": "德斯特星",
      "terrain": [ ... ],             # 省份多边形（原子），形状复用 terrain polygon（id/name/type/points）
      "referenceImages": [ ... ],     # 参考图垫底 + 比例尺校准（描图工作流）
      "createdAt": "...", "updatedAt": "..."
    }
  },
  "scenarios": {
    "<baseMapKey>/<slug>": {
      "id": "德斯特星/第一时代",
      "ownerKey": "德斯特星",
      "name": "...", "era": {...}, "order": 1,
      "polities": [ { "id", "name", "color" } ],          # 势力定义（色板）
      "ownership": { "<provinceId>": "<polityId>" },      # 省份归属表（EU4 模式核心）；缺省=无主
      "labels": [ { x, y, text, size, color } ],          # 历史地名 / 已消失地点
      "markers": [ ... ],                                  # 可选标记点
      "createdAt": "...", "updatedAt": "..."
    }
  }
}
```

- **省份是原子**：底图 terrain[] 画一次，六七个剧本共用；剧本编辑 = 点选省份 → 指派/清除势力（油漆桶式），**剧本层零多边形绘制**
- **渲染**：省份多边形按 ownership 查表填 polity 色（EU4 政治模式），无主省份用底图本色；境界线沿用省份描边
- **底图编辑 = PlanetMap 省份绘制套件迁移**：参考图垫底描图 + 笔刷 + 拆分合并 + 顶点编辑，通过 store 适配器（5-6 个方法）写入 baseMaps，undo 纪律不变
- **新建剧本**：空白归属表 / 拷贝上一时代 ownership+labels（JSON 断引用）——连续时代演进靠这个
- **入口**：WorldSelector 界面独立「⏳ 历史剧本」按钮（世界卡片之外，不混入常规导航）；剧本系统为 App 级全屏模式层（z-index ~1100），不注册 viewLevel、不进面包屑/树导航/搜索
- **维持不变**：era 手动 / order 排序 / 零回写 Obsidian（现在连挂载点都不依赖 Obsidian）/ 删除挂 confirm / 禁 alert/prompt

## 9. 视觉基线与卷轴决策（2026-09-08 mockup 实测，2026-09-09 v2 增补）

> 交互 mockup：`docs/mockups/scenario-map-mockup.html`（v1，41 省演示版）→ **`docs/mockups/scenario-map-v2.html`（v2，程序化架空世界，422/854 省）**。`?era=玥国&mode=wrap`（v1）/ `?mode=political&era=上古&density=mid`（v2）直达状态。无头验证与截图同目录。

### 卷轴决策：P0 采用「平铺·有界」，不做无缝卷轴

- **结论**：地图整图渲染在固定世界画布内（1600×800 逻辑坐标），拖拽平移限制在整图边界内（边界吸附钳制），滚轮缩放 0.8~3.2 倍。**东西方向不环绕、不滚动**。
- **理由（实测 mockup 后确认）**：
  1. 德斯特星剧本关注的势力疆域集中在中纬度两块大陆，极区已适度简略，东西环绕的真实收益≈0
  2. 卷轴模式要处理边缘省份跨界拆分（拓扑复杂度显著上升）、label/事件标注跨界绘制、minimap 语义割裂——全是纯成本
  3. 编辑器定位（描图/改归属/放地名）需要稳定的绝对坐标系，环绕坐标（`x % WORLD_W`）会让命中测试、undo 快照、参考图校准都多一层换算
  4. EU4 的卷轴是"全球战略游戏"的产物；司天剧本是"特定行星的历史切片查看器"，有界更贴合
- **mockup 中保留环绕切换按钮**仅作演示对比用，正式实现不移植
- 若未来要做大洲级/全球级剧本再看需求，P0~P2 均不涉及

### v3 相对 v2 的修正（踩坑全录，正式实现必须带上）

1. **海岸线造型**：v2 逐段随机扰动 = 锯齿+尖刺根源 → **谐波位移**（沿环弧长参数化的 2-4 个低频正弦叠加法向位移，基频≈每 700px 一大湾）+ **Chaikin 切角×2** + 4px 均匀重采样——平滑连续无毛刺
2. **缝合网格 7→3px**：v2 按 7px 网格重采样把平滑海岸切成 7px 折线段（锯齿「回潮」的第二根源）→ 3px 后折线段短到不可见
3. **海岸带禁抖**：缝合顶点抖动会把平滑海岸撕毛 → 距海岸 >6px 的顶点才抖
4. **平滑海岸描边叠加层**：省界折线退居质感层，眼睛跟随这道 1.6px 曲线（`#7d95ae`）
5. **小胞永不丢弃**：v2 把 <70px² 的省丢弃 = 露海洋底的洞（「迷你海洋割裂」的真正根源）→ 任何≥3 点的胞都渲染；缝合退化（<4 点）直接用裁剪原形
6. **描边减细**：0.9px `#8d8a82` → 0.6px `#a39f95`
7. **大陆布局**：37+ 圆重排——大半径主体圆（平滑弧）+ 宽根半岛（杜绝细颈）；内海用**显式负 blob（HOLES）挖海**；南部次大陆收窄并与南大陆拉开（v2 曾连成盘古大陆）；中央环礁移出主航道（v2 卡在海峡中间像陆桥）；新增西南大陆（类南美竖条）/东北大陆/远东岛链/南洋岛链/极南孤岛

### 管线（正式实现照此移植为 Node 脚本，一次性产 JSON）

1. **大陆骨架**：metaball 圆集（BLOBS 正 blob + HOLES 负 blob）→ Wyvill 紧支撑核（`t³`，影响半径外贡献恒 0）→ marching squares（Float64 场 + 插值分母保护 + 坐标钳制）→ 链式拼环（闭合环去重尾）→ **谐波位移 → Chaikin×2 → 4px 重采样 → 闭合环 RDP**（RDP 必须支持闭合环：首尾重复点产生零长度弦，整环塌成 2 点——实测踩坑）
2. **省份切分**：抖动网格站点（间距=√(陆地面积/目标省数)）→ 链式半平面沃罗诺伊 ∩ 大陆环 → **不设最小面积过滤**（v2 教训）
3. **无缝缝合**：3px 全局网格重采样（位置键共享）→ 海岸带外顶点按位置键 hash 抖 ±2.2px → 相邻省共享顶点序列
4. **分类**：地形 = 纬度带 × 距海 × 山脉 polyline 距离（9 类）；文化圈 = 大陆方位 + 内海邻近 + 群岛（8 圈占位）
5. **渲染要点**：smooth 海岸描边叠加层 + 细省界 + 染色混合地形纹理（政治视图 0.35 系数）

### 验证结论（v3.2 数据 + 截图双轨）
