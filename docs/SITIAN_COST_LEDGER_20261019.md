# 司天的成本账（2026-10-19）

> 暮雨的原话：「补个成本账，上一轮 token 消耗 **15,156,655**（基元律动 deepseek flash，
> 不知道是普通的 4.1 还是后训练的 1017 新版本 4.1），虽然缓存命中 **99%**，但这个成本还是挺高的。
> 希望以后注意控制成本，把 token 花在最需要的地方，减少浪费。」
>
> 这份文件只做两件事：**把量摆出来**（哪些东西在吃 token，多大），**把规则定下来**（下一轮怎么走）。
> 它不是自责清单，也不假装我能从会话里读到精确的 token 计数 —— 会话内拿不到那个数字，
> 所以下面的"粗估 token"是按**字节数 + 中文/代码的换算区间**算的，标注为估算，不当判据用。

---

## 1. 已知数字与它的含义

| 指标 | 数值 |
|---|---|
| 上一轮总消耗 | **15,156,655 tokens** |
| 缓存命中 | **99%** |
| 模型 | deepseek flash（具体是 4.1 还是 1017 后训练版未确认） |

结构推算（按 99% 命中）：

- ≈ **15.0M 是"缓存读"**，≈ **150k 是真正新读入的输入**；
- 输出（工具调用参数 + 回复正文）另计，通常显著小于输入，但**这一轮的长回复、长文档也在输出侧记账**。

⇒ **问题不是"某一处特别贵"，而是"总量是百万级、且高度重复"**：
同一份 217KB 的 `AGENTS.md`、同一份 542KB 的 `ScenarioMap.vue`、同一批 41 份 `docs/*.md`，
在一轮里被反复带进上下文。缓存把这些重复读降到了 1% 单价，**但没减少"重复"这件事本身**
—— 而 15M 这个体积，正是"重复 × 次数"的结果。

## 2. 大头在哪（体积是实测的，token 是估算的）

| 项 | 实测体积 | 粗估 token | 出现频率 |
|---|---|---|---|
| `AGENTS.md`（常驻指令） | **217.2 KB** / 638 行 | ~30–40k | **每一回合**（harness 已截断到 65KB，实际约 30k） |
| `src/renderer/src/components/ScenarioMap.vue` | **541.9 KB** / ~11k 行 | ~150k | 每次"整文件读" |
| `docs/*.md` 合计 41 个 | **595.6 KB** | ~160–200k | 一次"扫库/读旧文档"就接近全量 |
| `docs/ARCHITECTURE_MAP.md` | 34.5 KB | ~10k | 每轮常被整读 |
| 全量回归输出（123 用例） | — | ~10–20k | 每轮 1–3 次 |
| `AGENTS.md` 里的历史条目 | 658 行中的绝大部分 | — | 其中**只有极少数与当下任务相关** |

**结论：最大的可削减项是「常驻指令 + 历史条目」和「大文件整读」。** 两者都不是"必要成本"，
而是"图省事"的成本。

## 3. 下一轮的执行规则（按优先级）

1. **大文件只读窗口**：不整读任何 >5k 行的文件（`ScenarioMap.vue` 整读一次 ≈ 普通轮预算的 1/10）。
   定位用 `grep`，取上下文用 `read(offset, limit)`，一次 ≤150 行。
2. **全量回归只在"合并/收尾"跑一次**：改单点时只跑该用例 + 做一次**反向验证**（把修法关掉，
   期望它红）。这两件事的信息量比"123 条全绿"更大，成本只有它的几十分之一。
3. **回归日志只取尾部**：`run_tests.py` 的输出末尾就是结论（通过数 + 失败用例 + 那一条的 detail）；
   不要把 123 行逐条清单读回上下文。
4. **旧结论不再复现**：断点/交接文档里的「已完成且已验证（不要重做）」就是**免读清单** ——
   直接引用行号，不重读实现。
5. **一轮一条可感目标**：一条目标 → 一个探针 → 一个最小改动 → 一枚判据。
   同一路径失败两次就记账收手（把"试过什么、为什么不行"写成一行，别在原地再试第三次）。
6. **一次探针尽量多测**：起 lab（Vite + Electron）本身有固定成本；一个探针脚本里把
   ①②③ 三件事一起量完（本轮就是这么做的：拖动中的帧、抬手后的帧、一次落盘的成本）。
7. 🔴 **建议（需要暮雨拍板）**：把 `AGENTS.md` 的**历史条目**搬进 `docs/agents-archive/<主题>.md`，
   常驻只留「速查表 + 红线 + 索引」。按现在的体积估，每轮固定省 ~20k，
   而且新会话不必先把十几轮的历史全读一遍才能动手。**风险**：历史条目里的"坑"是资产，
   搬走要保留可检索的索引（一条一行，带关键词与文档锚点），否则下次又得从头踩。

## 4. 本轮的预算自查（第十九修·一）

- **只做了一件事**：手势闸门（自动保存顺延）+ 一枚判据 + 一次真实测量。
- **没有做**：② 去掉重复序列化、③ 挪出主线程、其余编辑器的基帧缓存、任何"扫库"。
  这几件的取舍理由写在 `docs/SITIAN_HANDOFF_20261019.md` §2，**不是漏掉，是刻意不做**。
- **没有重读旧文档**：开局只读了断点文档 111 行，没有读 41 份 `docs/*.md` 里的任何一份全文。
- **大文件**：`ScenarioMap.vue` 只读了 6 个窗口（每段 ≤120 行），没有整读。

## 5. 一句话

上一轮的 15.16M 不是"算力浪费在难题上"，而是**同一个上下文被反复搬运**。
把"整读"换成"窗口读"、把"全量回归"换成"单用例 + 反向验证"、把"历史条目"搬出常驻指令，
这三件事做完，同样的交付量应能压到**百万级以下**。
