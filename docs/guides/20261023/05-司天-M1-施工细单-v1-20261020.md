## 施工序（10 步，每步带完成判据）

### 步 0 · 对账与留底（开工第一动作）

1. `git pull` 对齐远端最新 main（云侧副本最多到 0.3.0/10-13，本地已推进更多——以 git log 实况为准，**绝不基于旧版本开工**）；
2. 415 省 .sitian 项目文件**整份复制留底**到工作目录外的备份位置（孤本不可重建，施工前后各一份）；

**完成判据**：git log 显示本地=远端最新；备份文件存在且字节数与原件一致；分支已建。

### 步 1 · 烂账实测（模块范围内四件，每件一行判定）

对下列四件逐件亲手实测（跑真机，不信旧报告——**agent 进度账不算数，实测才算**），格式："输入 X→实际现象 Y→判定"。判定选项：随本模块重做 / 砍 / 顺路修 / 无法复现记账：

| 件 | 测什么 |
|----|--------|
| 笔刷系（描轮廓/折线切割/涂归属） | 每种笔刷真画一笔，记录画出什么（预期=诡异几何）→判定必然是"重做"（细单已定），实测只为留底现状 |
| 顶点编辑器（含 0.3.0 框选多选/共享边界重算） | 实际画图工作流里用它编辑一次省界，记录**它跟画图流程哪里脱节**→去留判定：**"实际画图工作流真用得上"才保留重做，用不上就砍**（用户 10-20 实证："和实际画图完全是两回事"） |
| P0 全链（调边界→建势力→录易主→切片→PNG） | 全链真走一遍，断在哪记录哪→本细单步 9 将把它重建为自测链 |
| 聚落保存 bug（saveBurgEditor 疑似绕写闸门） | 复现一次→能修当天修（半天件），修不动记 commit 账 |

**完成判据**：四行判定进 commit message（不立文档，行账=commit 首行纪律）。

### 步 2 · Schema 定稿（照抄本节实现，字段只增不删）

> 设计已在此定死——这是"先定 schema 再写引擎"的落地。实现中确需调整：可以加字段，**不得删改既有字段语义**，调整理由记 commit。

```ts
/** 司天事件账本 schema v1（M1） */

// 事件类型（type 开放式，M1 实现这两个，后续模块可扩展战争/外交/聚落兴衰类）
type SiTianEventType =
  | "ledger.baseline"          // 基线快照（旧档迁移用）
  | "province.owner.changed";  // 省归属变更（M1 核心事件）

interface SiTianEvent {
  id: string;            // 唯一 id（uuid）
  worldId: string;       // 多世界预留；M1 恒 "default"，不写分叉逻辑
  epochId: string;       // 纪元预留（多历法）；M1 恒 "default"
  day: number;           // 绝对时间=自纪元起点第 N 天（整数，无历法假设）
  type: SiTianEventType;
  groupId?: string;      // 事务组：一次笔刷手势/一次批量操作=同组；undo/redo 以组为单位
  provenance: "brush" | "manual" | "ai-draft" | "import";
  payload: BaselinePayload | ProvinceOwnerChange;
}

interface ProvinceOwnerChange {
  provinceId: number;          // 现有省编码体系 id
  fromPolityId: number | null; // null=无主/未设定
  toPolityId: number | null;
  note?: string;               // 可选一句话剧本备注
}

interface BaselinePayload {
  owners: Record<number, number | null>; // 压平快照：{省id: 主polityId}
}

/** 展示层历法（纯 UI 概念，引擎不依赖；字段形状对齐 Azgaar lore.calendar 借种） */
interface CalendarConfig {
  yearLength: number;   // 一年多少天，默认 360
  epochs: { name: string; short: string; startDay: number }[]; // M1 单纪元
}
// day → "X纪 Y年" 换算=纯函数，独立模块
```

**Azgaar 借种**（仅字段形状参考，无代码可抄——实勘已证伪其历史层存在）：
- `lore.calendar { year, era, eraShort }` → CalendarConfig 字段形状来源；
- `campaigns { start, end, name }` → 将来战争类事件的形状参考（M1 不实现，记着）。

**.sitian 序列化兼容（415 孤本无损升级，关键设计）**：
- 打开旧档（无 events 节）→ 把**当前各省归属状态**压平为一条 `ledger.baseline` 事件（day=0）→ 此后新事件追加；
- 有 events 节 → 直接读账；
- 时间轴拖到 baseline 之前 → 恒显示 baseline 状态；
- **原数据一个字节都不丢**：culture/religion/polityId 等既有字段照旧，events 是新增节。一切写口走 guardWrite。

**回放语义**：任意时刻状态 = 纯函数 `replay(events, atDay)`：事件按 (day 升序, 追加序) 稳定排序，依序应用，`atDay` 后的事件忽略。baseline 事件=初始状态。

**Undo/Redo**：以事务组（groupId）为单位。undo=移除最后一个组→重放；redo=恢复刚移除的组→重放。撤销栈仅会话内存，不入档。一次笔刷手势跨多省=一组多事件，undo 一次撤整笔。**undo 栈止于最早的用户事务——baseline（迁移生成的组）永不可被撤**（防连续 undo 把地图清回无主态；哨兵 07:48 备忘）。

### 步 3 · 引擎实现+单测（纯逻辑，无 UI）

独立模块（建议 `src/ledger/`），不 import 任何渲染层。必须过的单测：

1. 空账+baseline → 回放=baseline 状态；
2. 追加 3 条 owner.changed（不同 day）→ 每个中间时刻断言正确；
3. 同 day 多事件 → 按追加序生效（排序稳定性）；
4. undo/redo 往返：涂（1 组 3 事件）→undo 复原→redo 回来→再 undo→稳定。**含 baseline 不可撤：连续 undo 到底=停在 baseline 状态，不是空账**；
5. 旧档迁移：无 events 节的对象→生成 baseline→序列化→重读→状态与原档逐省一致（**415 孤本兼容的判死题**）；
6. 事件量级压测：400 省×2000 事件全量回放 < 50ms（不到就先不做快照优化，记 commit 账留给后续）。

**完成判据**：6 项单测全绿+`src/ledger/` 零渲染层依赖。

### 步 4 · 笔刷重建+涂归属录事件（一笔=一组事件）

底座与管线：
- **perfect-freehand**（MIT，已双验）做笔迹生成：`getStroke(points, options)` → 笔迹多边形点集；
- 抄 **Excalidraw**（MIT）的命中测试模式：笔迹多边形 vs 省界（点在多边形内/线段求交）→ 命中省列表；
- 涂归属：每个命中省追加一条 `province.owner.changed`（同 groupId，provenance="brush"），撤销=撤组。

手感五件（终验演示件，施工时逐件自测）：
1. **涂色一笔多格**：一笔划过 3+ 省 → 全部变为当前笔刷势力色；
2. **吸管**：点已涂省 → 当前笔刷拾取该省归属；
3. **多选**：框选/shift 点选多省 → 批量改归属（批量=同组事件）；
4. **撤销重做往返**：涂一笔 → undo 地图复原 → redo 变更回来 → 再 undo → 稳定不漂；
5. **标签联动**：归属变更后地图标签/图例即时刷新。

手感参照：云侧《笔刷手感轮执行提示词》（10-07，自包含版）若在手边可照跑；拿不到就按上述五件验收行为实现，行为达标即算。

顶点编辑器：去留按步 1 实测判定执行——砍=移除入口不清数据（.sitian 里历史数据不动）；重做=仅在与笔刷工作流真衔接的前提下做，不做孤立功能。

**完成判据**：五件在真机各自演示通过+每笔事件落账（读 .sitian 文件确认 events 节真长了——**读盘判据，不信界面回显**）。

### 步 5 · 时间轴 UI+回放渲染

- 滑条：min=baseline(day 0)，max=最新事件 day；当前时刻显示"X纪 Y年"（CalendarConfig 换算）；
- 拖动用 change 事件（**松手生效**），拖动中显示提示，不做逐帧回放（性能坑对冲）；
- ±1 年步进按钮；
- 该时刻地图：省归属色= `replay(events, atDay)` 结果。

**完成判据**：涂 3 个不同年份的变更→拖轴到各年份，地图颜色与所录一致；拖回 day 0=原档状态。

### 步 6 · 导出（切片 PNG/SVG）

- 导出**当前时刻**地图（时间轴停在 t → 导出的就是 t 时刻的世界）：PNG+SVG，含标注（省名/归属名）；
- 对账现状：若现有导出管线可复用则复用，烂则重建（烂账处置纪律）；
- 验证：图像库读像素验**非空白**（既有判据）+415 省真实项目实测一次。

**完成判据**：导出文件打开=完整非空白地图+时间点标注正确。

### 步 7 · 病灶排雷+写口收口

- 施工中撞到静默失败类旧病灶 → **就地修**+commit 记账（不绕过不注释掉）；
- 本次新增的一切写口（事件追加/档保存）全部走 guardWrite 契约；
- 本次新增的每个 IPC 通道：注册即探针（发送-响应一次验通，不通不往下走）。

**完成判据**：新写口清单全部走 guardWrite+新 IPC 探针全绿（各一行 commit 账）。

### 步 8 · 全链自测（P0 链重建，副本制）

在**整份复制的 .sitian 副本**上跑（绝不直接碰 415 原档）：
1. 开副本（旧档）→ 确认自动生成 baseline，原状态无损；
2. 调边界 → 建势力 → 笔刷涂易主 → 拖时间轴回看 → 切片导出 PNG——全链一遍；
3. **反向探针**：保存→彻底关闭 app→重开→数据真变了（读盘验证）；
4. 无头截图留档（首选 `playwright _electron.launch`，备选其他无头方案）：baseline 时刻/中间时刻/最新时刻三张；
5. undo/redo 破坏性测试：连续 20 次 undo/redo 交叉后数据不漂。

**完成判据**：5 项全过+三张截图存档（放本模块交付目录，不入仓库主目录）。

### 步 9 · AI 翻译官子件（默认跳过）

**默认关**。仅当用户明确点头启用才做，且启用前先实测："markdown→.json 草案→现成 .json 导入口"这条 10-11 agent 报告的"零开发"路径**未经用户实测**（按总纲表注总则=未实测资产）——实测通过走现成口；不通过按实测量报开发（预算按"可能变有开发"口径）。

### 步 10 · 终验交付（用户出场一次）

交用户三步齐+五件：
- **录账**：亲手涂几个省的归属变更 → **拖时间轴**：亲眼看地图随年份变化 → **导切片**：PNG 拿去真用——全程无"地狱感"；
- 手感五件演示一个不掉链子；
- 415 省真实项目上跑，数据不丢（culture/religion/polityId 语义不丢，写口全 guardWrite）；
- 自测链全绿证据（副本+探针+读盘+三张截图）。

**终验通过 → 合流 main+打 tag（一次完成）；不通过 → 改到过为止，不开新模块。**
