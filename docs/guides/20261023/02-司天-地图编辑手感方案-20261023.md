## 一、先说结论

**司天画图烂，不是缺功能，是底盘烂。**

Windows 画图赢司天的三件事——**笔到线到、所见即所得、撤销可靠**——在司天全部是底盘件（渲染架构、保存时机、几何精度），而且**每一件的病灶都已经被量出数字或确诊**（见下表）。它们不是没做，是修了一半就停在半路。

同时**工具层方案已经就绪**（M1 细单步 4：perfect-freehand 笔迹 + Excalidraw 命中 + 手感五件）。但这里有一个**当前施工计划里最大的隐形坑**：

> **底盘三件欠账不补，新笔刷装上去，手感照样输 Windows 画图。**
> M1 步 4 没有把底盘件列为前置。涂归属笔刷重建得再漂亮，只要"编辑后半秒冻结"和"每帧全量重画"还在，你落笔的那一秒就是卡死的——你会得出"重建了也没用"的结论，而那不是笔刷的错。

手感 = 工具层 × 底盘层。**任何一层烂，都是烂。**这是本方案唯一的结构性判断，其余全是它的展开。

## 四、路径（不动三刀序列，把刀三升格为"手感总装"）

**序不变**：账本引擎 → 读料桥 → 笔刷（刀序你可当场调换）。改动只有两处：

**① 底盘三件可与刀一并行**（建议，等你点头）：
- 搬基帧缓存到 PlanetMap/AreaMap/InteriorView（ScenarioMap 已验证模式的平移，同构不同域，风险低）；
- 笔刷进脏矩形/局部重绘；
- 保存修法②（去重复序列化）。
- 理由：代码域与账本引擎（纯数据层）完全不踩（先例：v2.0 插单就是这么让资料线与 P0 并行的）；且**这三件不动，M1 步 4 交付那天就是你失望那天**——这是本方案要防的唯一事故。
- 代价：多一条并行线，会话预算多花几轮。你不点头就纯串行，刀三开工前先把底盘三件插进去，**顺序不能反**。

**② 刀三从"笔刷修复"升格为"手感总装"**：
- 工具层=M1 步 4 原方案（perfect-freehand + Excalidraw 命中 + 手感五件，方案完整不动）；
- 底盘层=上文三件（若未并行则此时补）；
- **验收=手感目标表逐条过真机**（B 档全过+E 档全过才叫"画得好"；Q 档进后续轮）。
- 施工节奏铁律（断点教训原文）："一条目标 → 一个探针 → 一个最小改动 → 一枚判据"，不再铺文档与守卫。
