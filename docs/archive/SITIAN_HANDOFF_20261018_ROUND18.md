## 1. 卡顿：先量，再修（不猜）

### 1.1 量出来的东西（真实 `docs/mockups/desite.map`：200 省 / 160 河 / 24018 骨架顶点 / 9975 格高度图）

整段 40s+ 会撞 CDP 15s 读超时，改成"页面里跑、Python 轮询 `window.__JANK`"）。
CPU 摊派：`scripts/tests/tools/_probe_cpu_profile.py`（CDP `Profiler`，按函数聚合自耗时）。

| 手势 | 每事件 handler | 帧 p50 | 帧 p95 | >33ms 的帧 |
|---|---|---|---|---|
| 省份自由绘制（修前） | **29.31 ms** | 44.5 ms | 72.2 ms | **27 / 44**（≈22fps） |
| 河笔拖笔（修前） | 3.42 ms | 16.6 ms | 24.9 ms | 0 |

CPU 采样（拖一圈 4 秒，5759 ms 样本）把修前的 29ms 摊开：

- **(program) 67%** —— 原生 canvas 光栅化本身（每帧把整张地图重画一遍：fill / stroke / lineTo / drawImage）；
- `conformToSkeleton` 最近点扫描 **590ms(10.6%) + 273ms(4.9%)** = O(笔迹点 × 24018 骨架顶点)；
- Vue 响应式代理读 **15%**（`get` 574ms + `isReadonly` 138ms + `createReactiveObject` 127ms）。

### 1.2 三条修法

1. **骨架最近顶点 → 空间索引**（`utils/provinceShape.js#nearestSkeletonVertex`）：
   格子边长 = threshold，查 3×3 邻域（半径 ≤ threshold 的圆盘最多与中心格 ±1 相交 = **完备**）；
   并列（同距离）时按 `seq` 排序后复用原比较逻辑 ⇒ 与朴素双循环**逐位一致**。
   调用点同时改成 `skeletonForTerrain(rawTerrain())` —— 骨架里躺着响应式代理时，
   **每次读 `.x/.y` 都要过 Vue 的 get 陷阱**（那一项占 15%）。
   实测：`conformToSkeleton` 590+273ms → **4.9ms**；`get` 574ms → 41ms。
2. **自动河那一段几何按数据引用缓存**（`autoRiverPartsFor`）：闸门 / 剪枝 / 成链 / 抽稀 / 裁岸线
   原来**每帧重算**（`render` 7.3ms → **14.3ms**，其中 `pruneRiverNetwork` 一项 4.2ms），
   而且每帧重建陆地掩膜。现在只在「河网换了 / 地形换了」时重算。
   ⚠️ 这一段原来是 `buildLandMask(rawTerrain())` 直接调用 —— 现在走 `getLandMask()`（按引用缓存）。
3. 🔴 **手势期「底图基帧」缓存**（`beginStrokeBase` / `buildStrokeBase` / `blitStrokeBase`）：
   按下时把「**没有草稿的那一帧**」渲染进离屏画布，拖动期间每帧只「贴这张图 + 画在动的浮层」，
   抬手即作废。绘图软件的分层就是这个意思，收益 = 上面表里 29ms → 2ms 的主因。
   - **为什么可以整帧缓存（不需要维护依赖键）**：启用的前提是"这一笔不改地图数据"
     （草稿全在组件本地状态：`freeTrace` / `riverDraft` / `riverDrag` / `dragPreview` / 框选矩形），
     且相机不动 —— 相机一动**立刻弃用并解甲**（否则"重建 + 贴图"比全量重画还贵一倍）。
   - **口径**：基帧只装"草稿之下的静态层"；草稿之上的四层（省名 / 势力名 / 浮雕 / 标记）与
     屏幕空间浮层**照常逐帧画** ⇒ 贴图帧与全量帧的**层叠顺序逐层相同、像素逐点相同**。
   - **安全阀**：`watch` 到 `terrain / rivers / heightmap / autoRivers / autoRiverSegments`
     换引用就**解甲**（撤销、导入、别的入口写入都不许贴旧图）。
   - 启用的手势：自由绘制 / 描轮廓 / 河笔 / 拖节点 / 顶点拖动 / 两种框选 / 折线切割；
     **不启用**：涂抹与高度·群系·文化·宗教笔刷（它们每帧真的在改底图数据）。
   - 机械计数 `strokeBaseStats = {builds, blits}` 供用例判"缓存真的在生效"（不靠墙钟时间）。

### 1.3 判据

- **`test_121_map_edit_stutter`**（新，6 段）：源码闸门（静态层受 `!blitted` 门控、动态层受
  `!strokeBaseBuilding` 排除、启用点 ≥6、滚轮作废、安全阀在、骨架索引 + `toRaw`）；
  机制（一次拖动 = **1 次建基帧 + N 次贴图**）；🔴 **贴图帧 ≡ 全量帧逐点相同**
  （683640 个像素逐个比对，差异 **0**）；相机一动解甲；数据一变解甲；抬手后不启用。
- Node 单测 **`test_skeleton_index.js`**（5 条）：与朴素实现**逐位一致**（20 条笔迹 × 8000 顶点，
  含并列距离）、并列取舍、阈值语义（`d < r` 严格）、**真的更快**（103ms → 4ms = 25.8×）、
  WeakMap 按数组身份不串味。

## 2. 河流：手绘 · 橡皮 · 一条撤销

### 2.1 预览 = 落库（「描点连线模拟器」的一半是这里来的）

修前：拖动预览走 `smoothWhileDrawing(riverDraft, 1, 18)`、**宽度写死 `0.7`**；
抬手落库走「抽稀 → 按弧长压到目标点数 → Chaikin」、宽度 `RIVER_WIDTH_DEFAULT`(3.5)
⇒ 画出来是一条细发丝，松手变成 8.4 屏幕像素的宽河，**形状也不是同一条**（松手会跳）。

修后：两条路共用 **`riverNodesFromDraft()`**（唯一几何链）+ 共用宽度 ⇒ **逐点相同**
（`test_122` b 段：预览 38 点 = 落库 38 点，`JSON.stringify` 相等）。
预览按 60ms 节流（手感线仍逐帧跟手）。

### 2.2 橡皮（`riverErase` / Shift+W / 底图编辑行里的「橡皮」按钮）

照抄绘图软件的橡皮：**按住抹过去就擦** —— 不需要先选中对象、不需要挑节点、不需要 Delete。

- 几何纯函数 `utils/riverErase.js`：`erasePolylineByStroke` / `planRiverErase`。
  🔴 **判定看"线的哪一段落在半径内"，不是"哪个节点落在里面"**：节点间距是按屏幕像素定的
  （30px），而一条很长的河会被 `RIVER_MAX_NODES`(72) 截住 ⇒ 间距可以远超橡皮直径，
  那时"只判节点"的橡皮**明明擦过去却没反应**。做法：先把折线按 `radius/2` **虚拟加密**再判，
  结果只保留「原节点 + 每段切口」⇒ 既不漏，也不会把节点数摊爆（切口最多每段两个）。
  🔴 边界**算"留"不算"擦"**（严格 `dist < radius`，与 `conformToSkeleton` 同口径）；
  留下的段短于 2 点丢弃（否则擦完留一个孤点 = "没擦干净"）。
- 半径 `RIVER_ERASE_RADIUS_PX = 18`（**屏幕像素**）：18 取在"半个节点间距(30px)"之上，
  保证垂直抹过河身时至少吃掉一个节点；画布上的擦除轨迹与笔尖圈**用同一个常量**画
  （画小一点就会出现"看起来没碰到却被擦掉"的判据/视觉不一致）。
- **只擦手画的河**（id 前缀 `river_`）：导入河是别人 `.map` 的数据、自动河是推演产物 ——
  擦了要么毁导入数据、要么下次生成又回来。抹到导入河上时**明确回一句**
  「橡皮没擦到河：只擦手画的河（导入河与自动河不动）」——绝不静默 no-op。
- **一次擦除 = 一条撤销**：写口 `applyBaseMapRiverEdit(baseMapKey, {patches, adds, removes})`
  （改 / 加 / 删**原子**，`execute` 只有一处；已登记 `writeGate` 的 `MEMORY_WRITE_CALLSITES`）。
  擦断 → 第一段留原 id（保住名字/宽度/归属），其余段成为新河（继承原宽度）。

### 2.3 顺带清掉一笔旧账：「画支流」从两条 undo 变一条

支流 = 「加这条河」+「在母河上插一个拐点」。修前是 `addBaseMapRiver` + `updateBaseMapRiver`
**两条 undo**（代码里诚实记着"本轮没做"）；现在走同一个原子写口 = **一条 undo**
（`test_119` 的母河节点 18→19 与落库 2 条的行为一字未变）。

## 3. 本轮**没做**（据实说，别以为做完了）

1. **其余三处地图编辑器还没上这套东西**：行星图（`PlanetMap`）、区域图（`AreaMap`）、
   室内图（`InteriorView`）仍是"每帧全量重画"。本轮只量了剧本底图（`ScenarioMap`）——
   暮雨说的"方方面面"如果包含那三处，需要各自量一次（探针可复用，把 `.scenario-map-container`
   换成对应容器即可）。
2. **一次性卡顿还剩两处**（本轮只修了"连续拖动"这条主线）：
   - **落库那条链 350ms**（`prov_land_ms`，真实底图）：压叠闸门（200 省逐点多边形判定）→
     一条 undo → 全量项目保存。压叠闸门有现成的空间化余地（按包围盒先筛）。
   - **自动保存一次 ~590ms**（探针里 `pan` 的 max 那一帧）：全量 `JSON.stringify` 4.5MB 载荷。
3. **河流的其余手感项**：橡皮目前**固定半径**（没接滚轮调半径那条统一契约）；
   没有"撤回上一步擦除"的专用按钮（靠 Ctrl+Z）；没有把**导入河**也纳入橡皮（有意不做）。
4. **节点编辑仍然在场**（没删）：它现在每次移动只花 0.15ms（卡顿那条已解），
   且 `test_106` / `test_119` / `test_114` 都压在它上面。要不要把它降级成"高级模式"需要拍板。
5. 上一轮交接里剩下的：星域编辑贴边自动整合 + 性能；行星地图（空图误判 / 一键清空色块 /
   选中文字描边）；支流删母河后的孤儿子河语义；吸管（真空白）；文化 / 宗教笔刷的写口契约
   漏登记 + 每 move 全量拷贝。
