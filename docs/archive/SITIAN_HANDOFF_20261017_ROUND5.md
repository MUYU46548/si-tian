## 1. 本轮做了什么：河流编辑三件（暮雨点名要过的）

来源：`docs/SITIAN_PROGRESS_AND_GAPS_20261017.md` §2.1 与交接文档 §2.2 的"用户明确要过、一直没做"。

### 1.1 多选（可 Discovery + 可视觉反馈）

- `selectedRiverIds`（整批）+ `selectedRiverId`（主选中，拖节点/加拐点仍只作用于它）。
- **Shift + 点** = 加选/移出（与省份的 Ctrl+点多选同一套手感）。
- 选中行文字变成「共 N 条（主：xxx）」；**高亮逐条画**：主选中暖白光晕，其余条目淡青光晕 + 细亮芯
  （以前只画一条，多选时其余几条在画布上毫无反馈 —— 正是他要的"多条同时选中的可视反馈"）。
- 换工具/取消选中都会清空整批（避免"看不见的选中"带进下一次操作）。

### 1.2 框选批量删河

- **Shift + 拖动** = 框选（虚线框；只画框不碰数据，抬手结算）。
- ⚠️ 判定**同时**含"顶点在框内"与"**线段穿过框**"（Liang–Barsky）：河的点很稀疏，
  只判顶点的话"框住河身中部"会一条都选不中 —— 判据与视觉不一致，用户会以为框选坏了。
  `test_114` 专门用一个**框里没有任何顶点**的小框做对照。
- **批量删除 = 一条撤销**（新增写口 `removeBaseMapRivers`）：用户的心智模型是"我删了这次选中的 5 条"，
  不是 5 步操作。`test_114` 的判据：删 3 条 → 0，按**一次** Ctrl+Z → **3 条全回来**（若被拆成 3 条命令只会回 1 条）。

### 1.3 手画河「裁到海岸线」按钮

- 两个入口都有文字按钮：选中行 `river-clip-coast`、河流工具行 `river-clip-coast-row`（可发现性纪律）。
- **只在他按下时裁**，不自动 —— 他自己说过有人就是要画进海里做三角洲/河口。
- 口径与"自动河 / 导入河裁海岸线"**完全同一份**：陆地判定 `makeRiverLandCheck(getLandMask())`
  （省份掩膜独占，第五修的结论）+ 裁剪算法 `clipPolylineToCoast`（新增写口 `applyBaseMapRiverPatches`，整批一条撤销）。
- 回执说清三件事：裁了几条 / 有几条整条在海里（**不自动删**）/ 一次操作 = 一条撤销。
  已经在陆地上的再点一次会明确说「已经在陆地上」，不再改动。
