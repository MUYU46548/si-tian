## 0. 三句话结论

1. **资料线不是“提取器坏了”，是“提取器只认地图实体”。** 你的库 1353 篇 Markdown，进扫描范围的只有 141 篇，最后成为节点的 120 个；人物、组织、事件、物品、年表这些“资料”在司天里**没有任何入口**。地标能跳，但跳过去只看到那一个地点的正文；双链一律把你送回 Obsidian——所以体感是“大号启动器”。
2. **手绘线不是“没有笔刷”，是“笔刷的几何与看到的不一致”。** 省份边界渲染用贝塞尔切线 `(next-prev)/3`（标准 Catmull-Rom 是 `/6`，等于两倍），角上外鼓、细碎处自交；布尔运算却只认顶点、不认曲线；笔刷半径默认 70 个世界单位、由 20 边形圆盘并出来，强度滑杆根本没参与几何。于是“画出来是诡异几何图形”。
3. **顺序：先资料线（隔离、可验收），再手绘线（先把几何链统一，再换笔迹引擎），最后 P0 第一张图。** 不要先装修剧本/外交/星系——那是在空壳上装修（架构收口 §4 的原话）。

**竞品结论：抄三件，不换引擎。** 抄 perfect-freehand 的笔迹、Azgaar 的“单文件分层 + 重生成边界”、obsidian-fantasy-map 的“地图要素 ↔ 笔记”绑定方式；不引入 React/tldraw/rough 做主链路，不搬任何非 MIT 代码。

**拍板记录（2026-10-19）**：排期取 **A 串行**（资料线 → 手绘线 → P0）；资料线取 **① 全库只读索引 + 阅读器 + 搜索**；手绘先试 **perfect-freehand（正常笔）**，若仍不达标再评估换画布引擎——判据与退路见 §6.1。暮雨补充：**司天至今只用于测试、从未真实使用**，所以“重做引擎”在时间上仍来得及，但必须由可测的失败触发，不能凭感觉提前重写。

### 1.3 抄三件（落成司天的三句话）

**A. 笔迹：perfect-freehand 直接做依赖。**
- `getStroke(points, { size, thinning, streamline, smoothing, simulatePressure, start, end })` → 轮廓点 → `Path2D`（Canvas 可直接填）。
- 轮廓默认含自交；司天已有 `polygon-clipping@0.15.7`，用 `union([stroke])` 压平即可（README 的 flatten 示例就是这条路）。
- `getStrokePoints` 单独可用：给“河流中心线/自由轮廓”做稳定与重采样，避免自己写 Chaikin + 抽稀两套。
- 参数口径：`thinning=0` 是等宽笔；负值让压力变细；`streamline` 是稳定器；`start/end.taper` 做笔锋。

**B. 数据：Azgaar 的“单文件分层 + 重生成边界”。**
司天项目文件已经是单文件 JSON（`.sitian`），方向一致；缺的是把“哪些层允许重算、哪些层永远保留”写成规矩：
- 可重算：地形/海岸线/自动河/派生标签（有源数据时可重建）；
- 不可重算：省份归属、势力、剧本账、用户坐标、手画河（没有外部资料可重建）；
- 重生成只能碰“可重算”层，且必须先出 diff 清单再写盘。
这条会直接约束以后的“重建海岸线”“换底图”“重导 .map”。

**C. 绑定：obsidian-fantasy-map 的“要素→笔记”。**
- 数据形状：`{ notePath, notePaths[], tags[], relations[] }` 挂在**地图要素**上，存在司天项目文件里，不写笔记。
- 解析方式：vault 内相对路径 + 标题/别名兜底；**不依赖目录**；重名进“候选”让人选。
- 交互：选中要素 → 侧栏渲染正文（marked 已有）→ 双链在应用内跳 → “在 Obsidian 中打开”降为次按钮。
- 这正是“地标跳设定页不是大号启动器”的最小实现。

### 1.4 明确不抄

- **tldraw**：任何代码/样式/图标/文档都不进仓（不是开源协议）。
- **obsidian-leaflet**：无 LICENSE = 保留所有权利，只借交互思路。
- **azgaarfmg-to-obsidianmd**：GPL 传染，只借流程。
- **rough.js 用于省界/海岸线**：抖动会让“看到的边界”与“数据边界”错位，正是当前病根之一；最多用于图例、指北针、标题。
- **换渲染引擎/换画布内核**：不换。Canvas2D + polygon-clipping 的组合已被 123 条用例和真实 20 万点数据验证过，换引擎是另一个量级的产品。

- 地图实体仍走 `extract-data`（决定哪些笔记能变成节点）；

### 6.1 画布引擎退路（暮雨 2026-10-19 补充后的口径）

暮雨原话：**“现在司天我从未用来做真实使用，都在测试，重做画布引擎还来得及。”** 这句话改变的是**成本判断**，不是**必要性判断**：现在重写的沉没成本低，但“该不该重写”仍然要由可测的失败来回答，否则会把“先修笔刷”拖成“先造引擎”。

**触发条件（满足任意两条才进入评估，不凭手感）**
1. **H0/T7-spike 不过**：真实 `desite.map`（200 省）上，一笔河/一笔轮廓的实时预览 **p95 帧 > 33ms**，或抬笔落库 **> 150ms**；或需要 **3 处以上手工补丁**才像笔。
2. **H1+H2 四轮后仍不过**：五件演示少于 4 件；或暮雨亲手试画仍判定“不像笔 / 画不出”。
3. **同一类缺陷第三次复发**：例如“预览≠落库”“看到的边界≠算到的边界”在换引擎后仍反复出现——说明病根在架构而不是笔刷。

**评估顺序（先便宜后贵）**
- **E1（推荐，若触发）自研“渲染内核”抽取**：把 camera / 场景对象 / 命中测试 / 脏矩形 / 导出适配器抽成**一份**实现，四个画布（ScenarioMap / PlanetMap / AreaMap / InteriorView）共用；**仍用 Canvas2D**。预计 4-6 轮。好处：不丢 123 条用例与已调好的几何，顺手解决“三个大 SFC 各写一套”的可维护性天花板。
- **E2 引入成熟 2D 场景引擎**（Konva / PixiJS / Leafer，均 MIT 系）：对象模型、事件、缓存现成；代价是 10k+ 点多边形、自定义命中、导出像素一致性、包体积与架构锁定，预计 6-10 轮。**只在 E1 撞墙时考虑。**
- **E3 换 WebGL/WebGPU（PixiJS v8 等）**：200 省的量级用不上；文字/矢量导出与像素级回归最难保住。**不建议。**

**结论**：先把 T8 与 T7-spike 做完再谈；引擎重写是“有判据的退路”，不是“默认路线”。

## 7. 成本、风险与红线

**预算（估）**：资料线 3 轮 ≈ 3-4M token；手绘线 4 轮 ≈ 5-6M；P0 ≈ 2M；合计 **10-12M**。按成本账的六条规则执行（窗口读 / 全量回归只在收尾 / 日志只取尾部 / 旧结论免读 / 一轮一条可感目标 / 一次探针多测）。

**风险表**

| 风险 | 触发 | 对策 |
|---|---|---|
| 库太大/图片太多 | 索引内存涨 | 索引只存元数据；正文懒加载；资源限大小/限类型 |
| 渲染层直接读文件 | 安全边界破 | 一律走主进程 IPC；路径必须在库根内；只读 |
| 两套事实源混流 | 项目态索引写画布 | 索引只读；画布仍只有 `projectStore` 一个写者 |
| 几何回归 | 改贝塞尔/布尔 | 像素探针 + 面积守恒 + 反向探针（破坏必红） |
| 新依赖进不了 Node 单测 | ESM/裸模块 | 像 `polygonBool` 一样注入；纯函数层单独测 |
| “手感”不可验收 | 主观 | 每组改动配可测代理（帧时/偏差/点数/撤销数）+ 暮雨终点人测 |
| 文档再次膨胀 | 每轮写长文 | 只写“断点/判据/证据”，不写现状散文；AGENTS 不再加条目 |

**红线（继承，不重复展开）**：无项目 = 只读；画布 → 项目只有一个写者；保存诚实；数据安全优先于手感；同一能力只许一份实现；不要整读大文件；AI 不画地图、不生成底图。
