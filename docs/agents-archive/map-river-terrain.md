- **A1/M1c：剧本地形「冻结导入 / 跟随行星」双模式（2026-09-25）**: `scenarioEditing` 新增 `importHeightmapFromPlanet(baseMapKey, planetId, { force, planetName })` —— 把行星当前地形**深拷贝**一份到底图（`cloneHeightmapForFreeze`：逐数组 `new Float32Array(...)`，**绝不共享引用**，也不复制运行期 `_spatialIndex`），走 undo，并记**纯展示**标注 `terrainFrozenFrom = { name, at }`（非引用、非真相）；底图已有地形时返回 `conflict`（`conflictKind='basemap-has-terrain'`），`force:true` 才覆盖。另有 `describeBaseMapTerrain(key)` → `{ mode: 'following'|'frozen'|'empty'|'none', planetId?, dangling?, from? }` 供 UI 显示（`following` 且行星已不存在时给 `dangling`，提示解绑/改冻结）。**为什么两种模式并存**：跟随 = 共用同一份 → 行星改地形会连带改剧本（适合当代同步构建）；冻结 = 独立副本 → 双向互不影响（适合历史存档剧本）。A1 文档最初否掉「复制」方案的理由（「复制即双源、漂移必然回归」）在**同步构建**场景成立，在**存档**场景恰恰相反 —— 存档要的就是漂移不发生。UI 在 `ScenarioMap` 底图区（工具栏「更多」里）加「地形：<状态> + 选行星 + 冻结导入 / 跟随 / 解绑」，两个按钮的 `title` 写明取舍（「复制一份」vs「会改到行星」）。⚠️ **不做任何自动绑定**（`.map` 导入只推 provinces 到行星，从不设 `planetId`）。回归 `test_68`（冻结/跟随**互为反面**：同一句「在剧本涂山」，冻结下行星必须不变、跟随下必须变）

- **造陆 v4.1：长条模式改成「脊柱 + 窄颈 + 横向半岛」，并修掉两处"海平面不是一个东西"的口径坑（2026-10-26）**：
  - **长条模式**（用户原话：「长条模式也只是'窄带'而不是天然的地峡/半岛链」）：v3/v4 的做法是
    "压扁的椭圆 + 纵向带窗"，出来是一条等宽香肠。现在改成 **脊柱上 5~7 个半径不等的核**
    （中段最宽、偶发窄颈 = 地峡）+ **脊柱整体弯曲** + **1~2 条横向半岛**垂直射进海里 + **两端各一枚小岛**
    （尾巴 = 岛链）；带窗半高 0.36 → 0.44（太窄会把横向半岛切掉）。
    判据：`test_152` 的面积加权主轴比 **长条 3.09 / 圆润 1.79**（改前 2.98），`test_landmass a4` 同口径。
  - 🔴 **两处"海平面"不是一个东西**（本轮实测踩到，两个症状一个根因）：
    `stats.seaLevel` 是**体元场**的分位数（长条 + 低占比时能低到 **12.28**），而合成地形的高度口径是 **20**。
    面板/出图工具拿前者去染后者 → 整片海显示成"浅水色"，画面上是**一块比外面更亮的方框**。
    现在 `relief.seaLevel` 是唯一口径（面板、出图工具、用例 a10 都读它）。
  - 🔴 **掩膜范围之外必须是海**：`landMask.isLand` 原来把界外坐标 `clamp` 到边上，而掩膜的 bbox 恰好是
    **陆地自己的包围盒** → 边缘一圈是陆地 → `terrainSynthesis` 网格的 pad 也变成陆地，
    栅格陆地面积从 32% 涨到 **41%**（`a10` 当场抓住）。改成界外一律 false。
  - `a10` 的判据也跟着改对：栅格只覆盖"陆地包围盒 + 一圈 pad"，所以**只能比面积、不能比占比**
    （实测 574k vs 多边形 576k 单位²，差 0.3%）。
  - **河流：本轮又试了三种，仍然不发货**（第三次记录，别再从头试）：
    ① `terrainErosion.js`（按流向场做 stream-power 下切，3 轮）= 把平行线**切得更深**，方向没变；
    ② 局部起伏放大 1.8×（高度 − 平滑高度）+ 各向同性中尺度噪声 = 地形更立体，河仍是沿主坡向的直线；
    ③ 不剪枝直接串链（`buildRiverPaths(traced.segments)`）+ 只收 endInSea 且 ≥12 格的链 = 河变长变少，
    但仍是一条条**近乎直线的细线**，且更稀疏。
    结论不变：**先有谷、才有河**；而"谷"要靠**多尺度的地形起伏**（不是 1~2 层噪声）才能出现。
    `terrainErosion.js` 的设计与常量留在本轮工作日志里，未入库（避免死代码）。
  - **验证状态（要照实说）**：`run_tests.py` 全量两轮都在跑到 ~test_83 时被**环境**打断

    61 个 Node 单测全绿、`test_60 / test_152 / test_153` 单跑全绿（本轮各跑两次）、
    `test_landmass` 11/11、`npm run build` 通过。**续跑第一件事仍是补一轮干净的全量** —— 换一台空闲机器或先关掉残留 Edge。

- **造陆 v4.2：河流终于出货 —— 关键不是调追踪，而是"先把地形弄皱"（2026-10-26，回照 `test_landmass a12` + `test_152`）**：
  前三次失败（v4 的直接追踪、起伏放大、`terrainErosion` 下切）都卡在同一个地方：
  **地形是一张均匀坡面**，D8 的"最陡方向"处处指向海岸 → 水只能平行下流 → 画面上是一排排 45° 直线。
  - ✅ **多尺度丘陵**（`landmass.js` 的 `scatterHills`）：在轮廓里撒 90~200 个半径 2~9 格、
    高度 1.2~6.5 点的丘与盆（半径按 `r^1.7` 幂律 = 小丘多、大丘少；16% 是负丘 = 盆地）。
    这一步把"穹顶 + 平行脊线"打散成"一堆大小不一的丘"，水才有地方**绕**和**并**。
  - ✅ **河成侵蚀**（`utils/terrainErosion.js`，2 轮、每轮一次 `traceRivers` 的流向场）：
    按河流功率 `Δh = k·A^0.45·S^0.9` 下切，并按局部落差封顶（≤55%，防止切出反坡坑）。
  - ✅ **不剪枝串链 + 直度闸门**：`pruneRiverNetwork` 会把链切碎（剪完再串，每条只剩 4~5 点 = 短棍），
    改成在完整流向场上 `buildRiverPaths`，再按"河口→源头直线距离 / 路径长 > 0.82"**丢掉过直的河**
    —— 那批正是均匀坡面上的并行水流。**宁可稀疏，也不要一排假河**。
  - 结果（seed 7 / 默认参数）：**38 条河 / 467 点，平均直度 0.77**；`a12` 守三条：
    条数 ≥6、**每个点都在陆地环内**（容差 5 单位，因为河是用 4 单位一格的掩膜裁的）、**不在湖里**。
  - **落库**：`provinceEditing.setBaseMapRivers`（整批替换，与 `setTerrain` 同性质）+ 造陆命令里
    与省份**同一条 undo**（`test_152` 新增：应用后 `rivers ≥ 1`、一次 Ctrl+Z 后 `rivers = 0`）。
    缩略图只画最长的 18 条（184px 上 50 多条会糊成一片蓝）。
  - ⚠️ **代价照实说**：单张候选 **~460ms**（v4 是 170ms）—— 3 张候选 ≈ 1.4s 的同步等待。
    多出来的时间在"丘陵 + 2 轮侵蚀 + 1 次追踪"（地形合成与海岸没变）。
  - 🔴 **踩到的两个"越界"**（都是 `a10`/`a12` 抓的）：① 丘的圆盘会跨过海岸线，把**海格**也抬过 20
    → 栅格陆地比海岸环多 21%（省份是按环切的，画面上"水里该有省却没有"）→ 现在只动陆地格；
