- **A1/M1c：剧本地形「冻结导入 / 跟随行星」双模式（2026-09-25）**: `scenarioEditing` 新增 `importHeightmapFromPlanet(baseMapKey, planetId, { force, planetName })` —— 把行星当前地形**深拷贝**一份到底图（`cloneHeightmapForFreeze`：逐数组 `new Float32Array(...)`，**绝不共享引用**，也不复制运行期 `_spatialIndex`），走 undo，并记**纯展示**标注 `terrainFrozenFrom = { name, at }`（非引用、非真相）；底图已有地形时返回 `conflict`（`conflictKind='basemap-has-terrain'`），`force:true` 才覆盖。另有 `describeBaseMapTerrain(key)` → `{ mode: 'following'|'frozen'|'empty'|'none', planetId?, dangling?, from? }` 供 UI 显示（`following` 且行星已不存在时给 `dangling`，提示解绑/改冻结）。**为什么两种模式并存**：跟随 = 共用同一份 → 行星改地形会连带改剧本（适合当代同步构建）；冻结 = 独立副本 → 双向互不影响（适合历史存档剧本）。A1 文档最初否掉「复制」方案的理由（「复制即双源、漂移必然回归」）在**同步构建**场景成立，在**存档**场景恰恰相反 —— 存档要的就是漂移不发生。UI 在 `ScenarioMap` 底图区（工具栏「更多」里）加「地形：<状态> + 选行星 + 冻结导入 / 跟随 / 解绑」，两个按钮的 `title` 写明取舍（「复制一份」vs「会改到行星」）。⚠️ **不做任何自动绑定**（`.map` 导入只推 provinces 到行星，从不设 `planetId`）。回归 `test_68`（冻结/跟随**互为反面**：同一句「在剧本涂山」，冻结下行星必须不变、跟随下必须变）

- **高度图放大的插值：双线性 → 双三次（2026-10-29，C4 治标）**: `utils/heightmapResample.js`
  的连续通道（`h`/`temp`/`prec`）从双线性换成 **Catmull-Rom（C1 连续）**。
  - **为什么**：双线性在格边界上斜率突变 → 等值线拐在格心上，光照/山体阴影把它放大成一条条直线棱
    （用户原话「地形模模糊糊 / 一格一格的」）。同样的格数，双三次的坡面是连续的。

    实测 `h=10c+r` 的 (0.5,0) 中点被算成 **4.375**（正解 5，偏 12%）。
    **一阶外插**能救直线，但二次面在边缘仍差 **1.03**（实测）→ 最终用**二阶**：
    `v(-1) = 3·v(0) − 3·v(1) + v(2)`（对二次以下精确）。
  - 🔴 **过冲必须夹持，而且只能夹真实格点**：Catmull-Rom 在阶跃处会冲出 `[a,b]`（造出不存在的山尖/负高度）；

    算进去等于给过冲开后门。

- **B 阶段 2 第 ④ 步：河能长出来（2026-10-29）**: FMG 模板地形**天生带大量封闭洼地** ——
  实测 8k 格上跑司天的自动河流（`riverTrace.traceRivers`，**不搬 FMG 的 `river.ts`**，那是第二套河网）
  结果 **0 条**：水全困在盆地，`reaches` 判据（有没有严格下降的路通向海）全灭。
  - **修法两件，缺一条都不行**：
    ① 生成后调 **`terrainSynthesis.fillDepressions`**（priority-flood，仓里唯一实现；本轮把它导出复用）抬平盆地，
       并把结果留在 **2 位小数**（ε 必须能在量化后活下来，否则又成了平层）；
    ② 覆盖率校准从"整体平移"改成 **"分位值当海岸线 + 陆上落差拉伸到 0..100"** ——
       平移会把**山峰一起压下去**（实测峰值只剩 ~50），而自动河流的**源头闸门是绝对高度 60**，河照样长不出来。
       `k` 全域只用一个（不做非线性），否则海岸坡度会变得不像地形。
  - 实测（`unit/test_fmg_heightmap.js` f7）：填洼 941 格 / 峰值 100 / 自动河流 **12 条**（6000 格）；
    模板对比（8k）：continents 20 条 / oldWorld 5 条 / archipelago 2 条（岛小，合理）；填洼**不改变陆地占比**（<0.5pp）。
  - **湖：本轮有意不做**。真湖要 洼地 → 湖面 → **出流** 三件套（FMG `lakes.ts` 的蒸发/出流平衡）；
    只把盆地挖成 18/19 会得到**没有出水口的死湖** → 河流在湖边断头（本项目明令禁止的形态）。
    湖泊仍走既有笔刷（平底 18/19、松手重标海陆），要自动化得按出流模型**替换**现有实现。
  - 产品形态：应用 FMG 地形后，河道由用户点既有「自动河流」生成（同一个追踪器、各自一条 undo）；
    面板 note 里已写明这一步 —— 不把两条命令偷偷并成一条，也不为它新开写口。
