# SiTian 笔记编写规范

> **目标**：让用户以最小的额外负担，写出能被 SiTian 正确提取的 Obsidian 笔记。

---

## 核心原则

1. **零侵入**：不改变用户的写作习惯，笔记依然可以在 Obsidian 中正常使用
2. **渐进增强**：不填任何额外字段也能工作，填写后地图更精确
3. **可选覆盖**：所有字段都是可选的，SiTian 会自动推断

---

## 快速开始

### 最小可用写法

只需要一个 frontmatter 字段：

```yaml
---
层级: 城市
---
```

SiTian 会自动：
- 从文件名提取节点名称
- 从文件夹结构推断父节点
- 从笔记内容推断 biome（生物群系）

### 推荐写法

```yaml
---
层级: 城市
上层区域: [[霜寒主星]]
标签:
  - 城市
  - 首都
  - biome/tundra
---

# 霜寒城

北方冰原上的永久定居点，常年积雪...
```

### 现在的读优先级（2026-09-27 起生效）

- **已经进过司天的地点**：机器属性以**司天（项目文件）为准**。你之后改笔记里的 `层级` / `上层区域` /
  `地点类型`，司天**不会再采纳** —— 要改就改司天里的那一份（点选界面 / 项目面板）。
- **还没进过司天的笔记**：第一次导入时，司天读它的 `层级` / `上层区域` / `地点类型` 当**初始值**；
  没有这些字段就按**目录与文件名后缀**推断（所以 `层级` 可以省略）。

> 一句话：**笔记里的这几个字段是「进门票」，不是「遥控器」。** 进门之后，属性归司天管。

### 删除边界清单（真要删字段那天，先过你的眼）

| 类别 | 字段 | 说明 |
|:---|:---|:---|
| **删** — 仅供司天用的机器字段 | `层级`、`上层区域`、`地点类型` | 搬家完成后司天不再读它们，删掉不影响司天里的任何数据 |
| **留** — 你亲手写的内容，绝不误伤 | 正文、`tags`/`标签`、`创建日期`、`publish`、`名称`/`别名`、`类别` | 常规字段，且 `标签`/`类别`/`名称`/`别名` 是**推断依据**（新笔记要靠它们），永远保留 |
| **退休不删** — 观察期不读、但暂留 | `coordinate`（旧版手动坐标）、早期写下的英文层级值 | 司天已不需要；留着零成本（Obsidian 对闲置字段无感），删的风险大于收益 |

> 真到删字段那天：**先把整个笔记文件夹复制一份另存**（报告 ④ 的「养老级主力」保险）再动手 ——
> 移动或删除是唯一「只剩一份」的时刻，保险全部挂在那一步之前。

## 字段参考

### 必须字段（让 SiTian 识别节点类型）

| 字段 | 说明 | 示例 |
|:---|:---|:---|
| `层级` | 节点类型（中文） | `世界`、`星域`、`星系`、`行星`、`城市`、`城镇`、`村庄`、`地点` |

**注意**：`层级` 也可以通过文件夹结构自动推断。比如笔记放在 `11 地理系统/星系/` 文件夹下，层级自动为 `星系`。

### 推荐字段（让地图更精确）

| 字段 | 说明 | 示例 |
|:---|:---|:---|
| `上层区域` | 父节点名称（wikilink 格式） | `[[霜寒主星]]`、`[[北境星域]]` |
| `标签` | 节点标签（用于自动推断 biome） | `biome/tundra`、`biome/forest` |

### 可选字段（高级用户）

| 字段 | 说明 | 示例 |
|:---|:---|:---|
| `地点类型` | 地点分类 | `自然`、`宗教`、`皇室`、`商业`、`工业`、`居住`、`公共`、`特殊` |

## Biome 自动推断

SiTian 会从笔记标题、正文、标签中自动推断生物群系（biome），用于地图着色。

### 推断规则（按优先级）

1. **标签精确匹配**：`#biome/tundra` → 冻原
2. **标题关键词**：标题包含"雪"、"冰"、"寒" → 冻原
3. **正文关键词**：正文包含"雨林"、"热带" → 热带雨林

### 支持的 Biome 类型

| Biome | 标签 | 关键词 |
|:---|:---|:---|
| 冻原 | `biome/tundra` | 雪、冰、冻、寒、极、霜 |
| 沙漠 | `biome/desert` | 沙、漠、旱、燥、荒 |
| 热带雨林 | `biome/rainforest` | 雨林、热带、潮湿、茂密 |
| 森林 | `biome/forest` | 林、树、木、森、松、柏 |
| 草原 | `biome/grassland` | 草原、草地、牧场、丘陵 |
| 湿地 | `biome/wetland` | 湿地、沼泽、湖泊、河流 |
| 山地 | `biome/mountain` | 山、峰、岭、崖、峡谷 |
| 海洋 | `biome/ocean` | 海、洋、深海、海岸 |
| 城市 | `biome/urban` | 城、镇、村、聚落 |

## 常见问题

### Q: 不填任何字段，SiTian 能识别吗？

**能**。SiTian 会：
- 从文件名提取节点名称
- 从文件夹结构推断层级
- 从笔记内容推断 biome

但显式填写 `层级` 和 `上层区域` 会更准确。

### Q: 上层区域怎么填？

使用 Obsidian 的 wikilink 格式：`[[节点名称]]`。

```yaml
上层区域: [[霜寒主星]]
```

### Q: 标签有什么用？

1. **自动推断 biome**：`#biome/tundra` → 冻原色
2. **区域提取**：共享相同标签的地点会被自动归为一个区域
3. **搜索过滤**：在 SiTian 中按标签筛选节点

### Q: 坐标怎么设置？

**不需要手动设置**。SiTian 会自动布局，用户可以在地图上拖拽调整。

如果一定要手动设置（比如从旧数据迁移），可以在 frontmatter 中添加：

```yaml
coordinate:
  x: 700
  y: 500
```

### Q: 重命名笔记后，地图上的节点会丢失吗？

**会 —— 当前版本如此，尚未修复**（2026-09-27 实测更正）。

司天认亲的依据是**笔记文件名**：节点 id 由文件名规范化而来（`extract-data.js:139` `id = normalizeId(parsed.fileName)`，例如 `青崖城.md` → `青崖城`）。改名即换 id，司天会把它视作一个**新节点**，原节点的坐标与编辑成果不会自动跟随，**而且当前没有任何提示**（静默）。

> **为什么不能靠 UUID**：代码里确实存在 `uuid` 字段，但它是**每次提取现场新生成**的随机值（`extract-data.js:151` `uuid: generateUUID()`），跨次提取永远匹配不上 —— `initializeCoordinates` 里那条按 uuid 取旧坐标的分支实际上是死代码，真正生效的稳定键只有文件名派生的 id。本文档此前写「SiTian 使用 UUID 作为节点的稳定标识，重命名后 UUID 不变，地图关联保留」，是一句**假承诺**，已按实况改写。
>
> **修复计划**：改名后由司天**主动提示重连**（断线检测）。它是「机器属性搬家」的前置步骤，见 `docs/ROADMAP_NEXT.md` 的决策记录 D5 与线 A 第 1 步（A-0）。
>
> **临时规避**：目前没有安全的自动路径。改名之前先确认该地点在司天里是否已有编辑成果（坐标、区域、建筑内部数据）；若有，改名后需在司天里手动把新节点接回原位。**项目模式下改名不会立刻反应**（项目态拒绝重新提取），但下一次提取时同样会断。

## 迁移指南

### 从旧版本 SiTian 迁移

如果你之前使用过 SiTian，笔记中可能有 `coordinate` 字段。这些字段会被保留，无需修改。

### 从其他工具迁移

如果你有现成的世界观数据（JSON、CSV 等），可以：
1. 写一个转换脚本，输出为 Obsidian Markdown 格式
2. 放在对应的文件夹中
3. 运行 `npm run extract-data` 提取

## 总结

| 操作 | 工作量 | 效果 |
|:---|:---|:---|
| 什么都不做 | 零 | 自动推断，基本可用 |
| 加 `层级` 字段 | 低 | 精确识别节点类型 |
| 加 `上层区域` | 低 | 精确层级关系 |
| 加 `biome/xxx` 标签 | 低 | 地图自动着色 |
| 手动设置坐标 | 中 | 精确控制位置 |

**建议**：先让 SiTian 自动推断，不满意再逐步添加字段。
