# SiTian 笔记编写规范

> **目标**：让用户以最小的额外负担，写出能被 SiTian 正确提取的 Obsidian 笔记。
>
> **本版（2026-10-06）的结论一句话**：`层级` / `上层区域` / `地点类型` 这三个**机器属性字段，你现在可以不写了** ——
> 结构归司天（`.sitian` 项目文件）、内容归笔记。详见下方「机器属性已归司天」一节。

---

## 核心原则

1. **零侵入**：不改变你的写作习惯，笔记依然可以在 Obsidian 中正常使用
2. **零 frontmatter 也能进**：一个字段都不填，司天照样能把笔记提取成节点（靠目录 / 文件名后缀 / 正文）
3. **结构归司天，内容归笔记**（2026-09-29 起）：层级、父子挂靠、地点类型由司天负责，
   你不用在 frontmatter 里人肉维护「机器属性」
4. **可选覆盖**：想让初次导入更精确，才需要写字段；不写就在司天里点/拖

---

## 快速开始

### 最小可用写法：零 frontmatter

```markdown
# 霜寒城

北方冰原上的永久定居点，常年积雪。它是 [[霜寒主星]] 上的定居点。
```

司天会自动：
- 从**文件名**取节点名称（`霜寒城`）
- 从**文件名后缀**判层级（`…城` → 城市）
- 从**正文里的 wikilink** 认出父级（`[[霜寒主星]]`）
- 从正文关键词推断 biome（「积雪」→ 冻原色）

### 想精确一点才写 frontmatter

```markdown
---
标签:
  - 城市
  - biome/tundra
---

# 霜寒城

...
```

> 注意这里**没有** `层级` / `上层区域` / `地点类型` —— 这三个已经不需要了（见下节）。
> `标签` 值得留：它同时影响 **biome 着色**、**区域自动提取**（共享 tag 的地点会归成一个区域）与**搜索过滤**。

## ✅ 机器属性已归司天（2026-09-29 落地，线 A 四件收官）

**结论：`层级` / `上层区域` / `地点类型` 可以不写了。**

分工定案是 **结构归司天（`.sitian` 项目文件）、内容归笔记（vault）**：这三个字段本质是
「人肉替机器录数据」，现在改由司天承载。四件已全部完成：
断线检测/重连（A-0）→ 存量搬家工具（A-1）→ 读优先级定案（A-2）→ **中文点选界面（A-3）**。

### 你现在最少要写什么

| 你想让司天知道的事 | 笔记侧最省力的做法 | 也可以完全不管，改用司天里做 |
|:---|:---|:---|
| **它是什么**（层级） | 放进对应文件夹（如 `11 地理系统/星系/`）**或**用文件名后缀（`…城`/`…镇`/`…村`/`…岛`/`…宫`/`…馆`/`…塔`…） | 详情面板「层级」下拉 |
| **它挂在谁下面**（父级） | 正文里写一次 `[[父级名]]` 就会自动认父 | 实体树**拖动**改父级 / 详情面板父级下拉 / **批量改父级** |
| **地点类型** | **不用写**（笔记里本来就没有） | 项目面板每行**中文点选**（8 个枚举；选项会兜住你已写的枚举外值） |
| **地图着色**（biome） | 建议留：`标签: [biome/tundra]`，或正文出现「雪/冰/寒…」 | 行星地图里直接涂色 |
| **叙事状态** | 可选：`status: destroyed`（中文键 `状态:` 也认） | 详情面板 |

> ⚠️ **父级的自动识别只有三条来源**，按优先级：
> ① frontmatter `上层区域` → ② **正文里第一个指向「更高层级」节点的 wikilink** → ③ 索引笔记
> （`地理系统索引.md`）里的缩进 wikilink（这条只覆盖 世界 → 星域 → 星系）。
>
> **都没有 → 它就是顶层孤儿**（不会乱挂、也不会报错）。孤儿在司天实体树里拖一下就能归位。
> ② 的注意点：正文里提了多个更高层节点时，取**出现顺序最靠前的那个**，不保证正好是你想要的那个 ——
> 要精确就在 frontmatter 写 `上层区域`（一句话的事），或者在司天里拖。

### 现在的读优先级

- **已经进过司天的地点**：机器属性以**司天（项目文件）为准**。你之后改笔记里的 `层级` / `上层区域` /
  `地点类型`，司天**不会再采纳** —— 要改就改司天里的那一份（中文点选 / 实体树拖动 / 批量改父级）。
- **还没进过司天的笔记**：第一次导入时，司天读它的 `层级` / `上层区域` / `地点类型` 当**初始值**；
  没有这些字段就按上面的表推断。

> 一句话：**笔记里的这几个字段是「进门票」，不是「遥控器」。** 进门之后，属性归司天管。

### 已进过司天的存量内容怎么办 —— 不用手动搬

**「导入知识库内容」本身就是搬家。** 拿真实库实测过：可认亲 **119/120**、待补 **0 处**、
已一致 **304**、冲突 **0**。
若之后笔记又改过 / 加过、想补进项目，用 `npm run migrate-vault-attrs`（默认 dry-run 出清点表，
`-- --apply` 才写盘；**只补空、绝不覆盖**项目里已有的值，不动笔记）。⚠️ 跑之前先在司天里关闭该项目。

### 删除边界清单（真要删字段那天，先过你的眼）

| 类别 | 字段 | 说明 |
|:---|:---|:---|
| **删** — 仅供司天用的机器字段 | `层级`、`上层区域`、`地点类型` | 搬家完成后司天不再读它们，删掉不影响司天里的任何数据 |
| **留** — 你亲手写的内容，绝不误伤 | 正文、`tags`/`标签`、`创建日期`、`publish`、`名称`/`别名`、`类别` | 常规字段，且 `标签`/`类别`/`名称`/`别名` 是**推断依据**（新笔记要靠它们），永远保留 |
| **退休不删** — 观察期不读、但暂留 | `coordinate`（旧版手动坐标）、早期写下的英文层级值 | 司天已不需要；留着零成本（Obsidian 对闲置字段无感），删的风险大于收益 |

> 真到删字段那天：**先把整个笔记文件夹复制一份另存**再动手 —— 移动或删除是唯一「只剩一份」的时刻，
> 保险全部挂在那一步之前。
> **而且没有必须删的理由**：闲置的 frontmatter 字段在 Obsidian 里是无感的，留着零成本。

## 字段参考（全是可选的）

> 零 frontmatter 也能进司天。下表只告诉你「想精确控制时写什么、不写会怎样」。

| 字段 | 作用 | 省略时会怎样 |
|:---|:---|:---|
| `层级` | 节点类型（中文） | 按**目录**或**文件名后缀**推断（见下节） |
| `上层区域` | 父节点名称（wikilink 格式） | 退而用**正文里的 wikilink** 认父；都没有就是顶层孤儿 |
| `地点类型` | 地点分类 | 留空 → 在司天项目面板里**中文点选**补（`自然`/`宗教`/`皇室`/`商业`/`工业`/`居住`/`公共`/`特殊`） |
| `标签`（`tags`） | 标签，用于 biome 推断 / 区域提取 / 搜索过滤 | 退而用正文关键词推断 biome；不会自动生成区域 |
| `名称` / `别名` | 识别用的补充名字 | 只用文件名 |
| `类别` | 层级推断的补充依据 | 只用文件名与目录 |
| `status`（或 `状态`） | 叙事状态（如 `destroyed`） | 视作未设置（**司天只读、不回写**） |
| `coordinate` | 旧版手动坐标 | **不需要写**：司天自动布局，拖拽调整即可（坐标只存 JSON 缓存，永不写回笔记） |

## 层级怎么被推断出来

### 1. 地理系统（`11 地理系统/` 下）

优先级：`层级` 字段 → **目录名关键词** → 父级目录 → `unknown`。

| 层级 | 中文 | 目录名认得的词 |
|:---|:---|:---|
| `world` | 世界 | 世界（索引笔记） |
| `star_domain` | 星域 | 星域 |
| `galaxy` | 星系 | 星系 |
| `planet` | 行星 | 行星 |
| `star` / `moon` | 恒星 / 卫星 | 恒星 / 卫星 |
| `region` | 区域 | 区域 |

### 2. 场景地点（`02 场景地点/` 下）—— **靠文件名后缀，不靠子目录**

优先级：`层级` 字段 → **文件名/别名后缀** → `标签` → 正文关键词 → 兜底 `location`。

| 后缀 | 判成 |
|:---|:---|
| `…城` | 城市 |
| `…镇` | 城镇 |
| `…村` | 村庄 |
| `…岛`、`…半岛` | 区域（岛屿是区域，不是城镇） |
| `…府 / 宫 / 殿 / 馆 / 院 / 楼 / 塔 / 寺 / 庙 / 坛 / 阁 / 堂 / 厅 / 站 / 厂 / 店 / 邸 / 社 / 室 / 所 / 库 / 台 …` | 设施 |

> **这条后缀表是最省力的纪律**：给地点起名时带上粒度字（`青崖城` / `苇塘镇` / `听雨馆`），
> 司天立刻判对，一个字段都不用写。名字里没有这些字又想要粒度 → 填 `层级` 字段，或在司天里点。

## Biome 自动推断

SiTian 会从笔记标题、正文、标签中自动推断生物群系（biome），用于地图着色。

### 推断规则（按优先级）

1. **标签精确匹配**：`#biome/tundra` → 冻原
2. **标题关键词**：标题包含"雪"、"冰"、"寒" → 冻原
3. **正文关键词**：正文包含"雨林"、"热带" → 热带雨林

### 支持的 Biome 类型

| Biome | 标签 | 关键词 |
|:---|:---|:---|
| 冻原 | `biome/tundra` | 雪、冰、冻、寒、极、霜 |
| 沙漠 | `biome/desert` | 沙、漠、旱、燥、荒 |
| 热带雨林 | `biome/rainforest` | 雨林、热带、潮湿、茂密 |
| 森林 | `biome/forest` | 林、树、木、森、松、柏 |
| 草原 | `biome/grassland` | 草原、草地、牧场、丘陵 |
| 湿地 | `biome/wetland` | 湿地、沼泽、湖泊、河流 |
| 山地 | `biome/mountain` | 山、峰、岭、崖、峡谷 |
| 海洋 | `biome/ocean` | 海、洋、深海、海岸 |
| 城市 | `biome/urban` | 城、镇、村、聚落 |

## 完整示例

# 霜寒城

霜寒主星上的定居点，北方冰原的永久聚落，常年积雪与狂风。

## 常见问题

### Q: 不填任何字段，SiTian 能识别吗？

**能**。司天会从文件名取名称、从目录/后缀判层级、从正文 wikilink 认父级、从正文关键词推 biome。

### Q: `层级` / `上层区域` / `地点类型` 到底还要不要写？

**可以不写**（2026-09-29 起）。结构归司天。三个字段现在的角色只是「第一次导入时的初始值 / 进门票」，
进门之后归司天管（见上文「机器属性已归司天」）。

### Q: 上层区域怎么填？

使用 Obsidian 的 wikilink 格式：`上层区域: [[霜寒主星]]`。
不写的话，司天会退而用**正文里第一个指向更高层节点的 wikilink** 认父。

### Q: `地点类型` 在哪补？

司天 → 项目面板 → 实体列表每行有**类型下拉**（中文点选，8 个枚举），
还有「只看空白」过滤（全部 / 类型为空 / 挂靠为空 / 任一为空）。这是搬家后设类型的唯一入口。

### Q: 标签有什么用？

1. **自动推断 biome**：`#biome/tundra` → 冻原色
2. **区域提取**：共享相同标签的地点（≥2 个）会被自动归为一个区域
3. **搜索过滤**：在 SiTian 中按标签筛选节点

### Q: 坐标怎么设置？

**不需要手动设置**。SiTian 会自动布局，用户可以在地图上拖拽调整。
坐标只存在于 JSON 缓存 / 项目文件里，**永远不会写回 Markdown**。

### Q: 重命名笔记后，地图上的节点会丢失吗？

**不会丢了 —— 2026-09-27 已修（`test_75` 守）。**

旧版确实会：认亲钥匙是笔记的**相对路径**，改名即断链，而且没有任何提示（静默）。
现在司天在项目面板提供「**检查笔记改名**」：列出断线节点 + 可读理由 + 推荐候选，
你确认后**重连**（节点 id 不变，坐标 / 地图 / 区域数据全部保留，一条 undo 可撤）。
目标 id 已被占用时会拒绝并**点名**冲突对象，不会静默改名。

> 仍然建议：**先在司天里改，再改笔记**（或改完笔记立刻点一次「检查笔记改名」）。
> 断线检测是兜底，不是让你随便改的理由。

## 迁移指南

### 从旧版本 SiTian 迁移

笔记里的 `coordinate` 字段会被保留，无需修改。
`层级` / `上层区域` / `地点类型` 建议**原样留着**（零成本），要删就先备份整个笔记文件夹。

### 从其他工具迁移

如果你有现成的世界观数据（JSON、CSV 等），可以：
1. 写一个转换脚本，输出为 Obsidian Markdown 格式
2. 放在对应的文件夹中（或让文件名带粒度后缀）
3. 运行 `npm run extract-data` 提取

## 总结

| 操作 | 工作量 | 效果 |
|:---|:---|:---|
| 什么都不做 | **零** | 自动推断，基本可用 |
| 文件名带粒度后缀（`…城`/`…镇`/`…宫`） | 零（起名时顺手） | 层级判得准 |
| 正文里提一次 `[[父级名]]` | 零（本来就会写） | 父级挂得对 |
| 加 `biome/xxx` 标签 | 低 | 地图自动着色 |
| 在司天里中文点选「地点类型」 | 低（点一下） | 类型补全（笔记里本来就没有） |
| 手写 `层级` / `上层区域` | 低（已非必需） | 首次导入最精确 |

**建议**：让司天自动推断，不满意再在司天里点/拖 —— **不必再为写笔记而写 YAML**。
