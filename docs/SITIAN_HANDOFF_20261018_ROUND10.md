## 1. 一处容易被忽略的连带修复：导出图幅

导出原先只按 `coordinate` 取包围盒。星域在布局里是**环上**（半径 630）、星系在**簇内**，
这些位置原先根本不在 bbox 里 —— 修好坐标源之后若不改 bbox，环上的星域会被**裁到画布外**。
现在 `placed` 列表把布局位置一起纳入（world/planet/city 仍按自己的 coordinate 参与）。

## 2. 判据（`test_117_galaxy_export_same_source.py`，两段）

- **f0 源码闸门**：两边都 import 共享模块；`App.vue` 不许再有第二套凸包/配色/节点色/星云；
  导出必须调用 `layoutDomains` / `layoutGalaxies` / `factionBorders` / `hyperlaneColor` / `nodeColor` / `nodeRadius` / `STARFIELD`。
- **f1 插桩导出**：**覆盖 `CanvasRenderingContext2D.prototype.arc`**，记录所有半径 ≥ 5 的"节点圆"
  （星尘半径 ≤ 1.2，天然排除），再与"用同一份共享函数、同一份 store 数据算出来的期望位置"**逐点配对**
  （容差 0.75）→ 实测 **108/108 全中**；并单独断言：星域在环上 `(0,-630)`、**不在**遗留 coordinate `(737,131)` 上；
  星系在簇内 `(95.5,-600.4)`、**不在**自己的旧 coordinate 上。
- **f2 像素**：把导出产物（覆盖 `toBlob` / `createObjectURL` 抓 blob）解成 PNG 画到探针画布 →
  **`#ffd700` 像素必须为 0**、星系色（`#6b5b95` 等）像素 > 0、位图尺寸合理（实测 **5468×5518**）。
- **Node 单测** `test_galaxy_layout.js` **14 条**：函数口径（含 `resolveDomainColor` 三级优先、环形半径 630、
  `userMoved` 门、无 coordinate 的星系也要有位置、星系数 < 3 不许消失、外扩 pad 单一、航道 4 类互不相同、
  星云谱在世界坐标里固定），外加一条**源码守卫**（"两边都 import 这一份、且 App 里没有第二套实现"）。

## 3. 反向验证（一枚一验）

把导出**临时改回旧口径**（按 `coordinate` 画 + 星系固定金色）→ **6 条具名红**：

- 「**星域画在了遗留 coordinate (737,131) 上 —— 与画布不同源**」
- 「星系 曜川星系 没有画在布局位置 (95.5,-600.4)」
- 「**星系画在了自己的旧 coordinate 上 —— 与画布不同源**」
- 「**导出图里还有 8752 个 #ffd700 像素 —— 星系仍用旧的固定金色**」

## 4. 本轮踩到的两个用例侧坑（都写进 AGENTS 了）

1. **导出菜单默认不挂载**（`panelsStore.isOpen('export')`）→ 必须先点工具栏「导出」按钮；
   而**点完要等一拍**才查得到菜单（Vue 的 DOM 更新是异步的 —— 本项目第 N 次踩）。
2. **导出是"同步绘制 + 异步 toBlob"**：图很大（5468×5518），PNG 编码要好几百毫秒
   → 必须**轮询等产物**（`window.__exportBlob`），否则下一段拿到 null（第一版就踩了）。
