## 结论先行

1. **联动：砍。** 与报告同向。但报告把“砍”写成删三件套，实际要退回的是五层里的三层（索引 / 阅读跳转 / 候选导入），
   而且**砍之前必须先改 `AGENTS.md` 的核心原则 1** —— 否则下一轮 agent 会按“Markdown 为唯一事实源”把它原样加回来。
2. **提取：留，但降级为一次性导入。** 报告把“读 vault”整块判出局，在仓里对应的是**两件不同的事**：
   一次性导入（把已有库变成项目）和实时联动（库一变就重读）。前者是唯一的入口，砍了你的 140 个地理实体进不来；
   后者才是它说的那份债。**这一条是本文与报告的主要分歧。**
3. **报告的第一优先级已经在跑。** 存档早就有版本号：`PROJECT_VERSION = '1.0.0'` + `MIGRATIONS` 迁移框架 +
   更高版本拒收（`src/renderer/src/utils/projectSchema.js:61 / 112 / 516`）。真正没做的是它列的另两条
   （空值不落盘、没有“完成态”的判据），而这两条成本极低、且能落成判据。

## 二、报告的三处事实误差（都有仓内证据）

### 1. “存档里带版本号字段 —— 现在做死”

**已经有了，而且是完整的迁移框架，不是光一个整数。**

- `PROJECT_VERSION = '1.0.0'`（`projectSchema.js:61`）
- 迁移表与逐版升级路径：`MIGRATIONS`（`:113`，**目前是空表** —— 框架通了、一条迁移都还没写，这正是“首个版本”该有的形状）、
  `migrateProject()`（`:658`）；迁移任何一步抛错都变成“拒绝加载、磁盘不动”（`:680`）
- 版本高于当前 → 直接拒收并提示升级（`:516`、`:662`）
- 缺 `version` → 按当前版本处理并记一条 `problems`（`:514`），**不拦**

所以报告这一条从“现在做死”降级为“**已满足，维持**”。它的价值判断没错（旧档要有抓手），只是这份抓手早就在了。

### 2. “现阶段不存在任何校验器”

**有一个，但它拦的不是空字段。** `validateProject()`（`projectSchema.js:507`）只在四种情况下返回失败：
内容不是对象、版本高于当前、解析失败、迁移/校验抛异常。
其余全部是**就地修复 + 记 `problems`**：缺名字用 id 顶（`:544`）、未知层级归 `unknown`（`:538`）、悬空父级置空（`:560`）。

这条对红线的意义是好的：**数据层现在确实是“全可空”**，报告 §3-1 想防的那个坑没被踩。
但它没被写进红线、也没有判据守着 —— 哪天有人在 `validateProject` 里加一句“缺 layer 就拒收”，
界面的宽容会从数据层被绕回来，而没有任何用例会红。**这才是该补的东西**（见 §六）。

### 3. “没有需要保护的存量，所以兼容性债零利率”

**这句话只对 `.sitian` 成立，对 vault 不成立。**

- 报告原话“从未被我真实使用，从没放过任何真实地图数据”是 **11-03 对司天自己画的地图**说的 —— 成立。
- 但 vault 里有一份三年的存量：11-07 那次只读扫描读到 **1,375 篇**、**140 个地理实体**、4 个星域挂在同一个世界下。
  那是**世界上唯一一份**把你这个世界结构化过的东西。

“格式随时剧变、旧档直接作废”对 `.sitian` 是正确姿势；对“把 vault 读进来”这条链路不成立 ——
读进来之后它就是你唯一的副本，作废一次等于重做一次导入。所以 **A 层的正确形态不是“随时可扔”，
是“导入一次、之后与库解耦”**。

## 三、报告漏掉的两个连锁后果（这是它建议里最容易翻车的地方）

### 1. `draft` 的定义挂在 `sourcePath` 上 —— vault 一走，整棵树变虚线

`geodata.js:1772`：`draft: !e.sourcePath`。

后果链条：vault 出局 → 所有实体都没有 `sourcePath` → 全部 `draft === true` →
节点面板 / 区域图 / 行星图全部显示“暂存节点”虚线边框 + “转正”按钮，
而那个按钮的动作是 `createObsidianNote()` **往库里写 `.md`**（`PlanetMap.vue:1924`、`NodeDetailPanel.vue:1028`）。

也就是说：砍联动不是“少一个跳转”，是**“什么叫一条已经建好的条目”这个定义要重写**。
`sourcePath` 在渲染层有 **125 处消费**，不是删得掉的孤立字段。

### 2. 与 `AGENTS.md` 核心原则 1 正面冲突

原则 1 现在写的是“**Markdown 为唯一事实源**”。报告的地基是“司天自包含、vault 不是数据源”。
两者不能同时为真。砍联动必须**同一次提交里改掉原则 1**，并写明新的口径（建议见 §六-6），
否则这就是下一个“反复提出从未实装”的来源。

## 九、真库实测：140 个实体到底能不能自动搬进去（2026-11-08 补）

命令（只读，库内一字节未动，跑完指纹对拍通过）：

```
node scripts/vault-scan.mjs --vault "<库根>" \
  --out build/_vault-audit-20261108 --geodata
```

产物即“导入后司天会得到的那棵树”。读数：

```
节点总数        143   （141 有真笔记 + 2 个由双链补出的空壳）
连到根          143 / 143 = 100%
父不存在的节点  0        环 0
父来源          你自己 frontmatter 124 ｜ 索引文件 4 ｜ 双链推断 4 ｜ 无父 9 ｜ 空壳 2
深度            1 ~ 5
最深一条        世界 > 星域 > 星系 > 卫星 > 建筑 > 房间（6 级；专名不入库）
重名撞 id       0 组
```

三个世界已经长成形了：世界甲下 5 个（4 个星域 + 1 个地点）、世界乙下 4 个星域、
世界丙下面 0 个（这条世界本来就没写内容）。

**结论一：机器只猜了 6 个关系，不是 140 个。** 133/143（93%）的父子关系来自你自己写的字
（frontmatter 或索引文件）。4 条双链推断（地点→所在世界、建筑→所在城、船→停靠地）逐条看都是对的。
所以“非人工提取做不到”这句话，在**第一次导入**上不成立。

### 9.3 真正会翻车的不是第一次导入，是第二次

`mergeVaultPayload`（`projectStore.js:265-275`）是**只补缺不覆盖**、按 `id`（= 名字）匹配：

| 你在 Obsidian 里做的事 | 重新导入后 |
|---|---|
| 给某篇笔记补 `上层区域` | **不生效**（同名 id 已存在 → 跳过） |
| 给笔记改名 | 新名字 = 新 id → **多一份**，旧的成孤儿 |
| 新写一篇地点 | 正常补进来 |
| 删掉一篇笔记 | 项目里那条**不会消失**（只增不减） |

`extract-data.js:207` 的 `uuid` 是 `Math.random()` 现生成的（`generateUUID()`），**每次提取都不同**，
所以稳定身份只能靠 id（名字）。而处理“改名 → 孤儿”的唯一工具是
`projectStore.scanBrokenLinks` / `relinkEntity` + `utils/vaultRelink.js` 的候选打分 —— 正是 C2 层。

**所以 §四 的口径要改：C2（对账/重连）不能跟着 C1（绑定 UI）一起砍。**
它服务的不再是“点图看原文”，而是“库改了，项目怎么跟上”。砍了它，“140 全搬”就变成
“搬进来那天的快照，之后库怎么改司天都不知道”，而且没有任何机制会告诉你。

### 9.7 重新导入改成“按 sourcePath 更新”（选 A）

`mergeVaultPayload`（`projectStore.js`）以前是“只补缺、不覆盖”，于是你在 Obsidian 里改
`上层区域` / `层级`，重导**不生效**。现在：

- 按 **`sourcePath`** 认亲（不是按名字：名字会撞、也会改）；
- 认亲成功 → 只更新机器字段：`layer` / `layerLabel` / `parentId` / `placeType` / `tags` / `wikilinks` / `status`；
- **保留**：`name`（你在司天改过的显示名）、`coordinate`（画布上拖的位置）、`uuid` 与两个时间戳；
- 载荷里没有的条目 → 一动不动（笔记删了，项目里那条还在，刻意不替你删）；
- 合并后悬空的 `parentId` 一次收口（换对象，不就地改 —— 这条函数是纯函数）；
- 返回 `merged.updated`，界面上写“新增 N / 更新 N”，只更新时也不会被当成“没有新东西”。

判据：`test_58_import_from_vault` 的 c3 段整段改写（旧断言是“机器属性以项目为准”，现在反过来），
新增一条反向探针：**载荷里没有这篇时，项目里那条连一个字段都不许动**。

⚠️ 这条**推翻了 2026-09-27 的 A-2 定案**（“机器属性一律以项目为准”）。旧的 A-2 结论留在
`docs/plan/DECISIONS_20261104.md` 与 test_58 的历史注释里，口径以本节为准。
