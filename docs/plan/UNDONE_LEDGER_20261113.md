> **状态口径**：`未做` / `半做`（有数据没 UI、或有 UI 没判据）/ `需拍板`（不是工程问题）/ `阻塞`（等外部）。

   比整个区域还大。改成"屏幕像素定尺 + 夹取"：缩远恒定 34px，拉近按真实比例放大，上限 220px。
   —— 这样"大房子比小房子大"仍成立，但不会失控。

顺带修了两个我自己的公式错误（`pxW` 漏乘 zoom、命中框多除 zoom），都是自测探针抓出来的。

## 二十、2026-11-15 追加：异形平面的精确轮廓（用户：加引擎依赖无所谓）

上一节留的已知限制是"凸包会把 L 形/凹形的凹处填平"，并注明"要精确轮廓得上多边形布尔"。
用户拍板：**加依赖无所谓，只看结果**。这一轮把那一刀做了。

### 做法

`interior/buildingSymbol.js` 的占地从“墙端点的凸包”换成“**墙矩形的布尔并集**”：

| 步骤 | 说明 |
|---|---|
| 墙 → 矩形 | 每面墙按厚度四向扩（两端各半个墙厚，转角处自然重叠） |
| 并集 | `polygon-clipping@0.15.7`（纯 default 导出，`import * as pc` 会拿到 `{default:{}}` 静默失效） |
| 结果整理 | 每块 = 外环 + 洞；不相连的楼自然分成多块 |
| 兜底 | 引擎抛异常时退回凸包，并标 `exact:false`（不让整张地图画不出来） |

### 三个连带决定（都是"几何没法定，只能定语义"）

1. **洞默认填掉**。几何上区分不了"房间内部"和"院子"——一间房四面墙围合、一个四合院四面房围合，
   拓扑完全一样。默认语义是"这栋楼占多大地盘"，画成实心最不容易误读。
   要看院子显式传 `courtyard: true`，那时只留 ≥35% 面积的大洞（小洞是楼梯井，填掉）。
2. **脊线不再用外接矩形中心线**。实测 L 形 612×612 的中心线正好落在凹口那条边上（差 6cm，
   缩到 108px 时等于重合），画出来就是"没有脊线"。改成 `skeletonRidge`：沿两个轴各切 14 条带、
   取每带轮廓中点连成折线（**两个轴都算**——L 形外接矩形是正方形，长轴取哪个是任意解）。
3. **贴着轮廓的骨架段丢掉**。L 形"重叠区"那条中线离凹口边只有 6cm，画出来像双线。
   阈值按符号尺度取（短边 10%），丢掉之后每臂各剩一条干净的屋面线。

### 证据

- 单测 `unit/test_building_symbol` **19/19**：L 形外环 6 点、凹口点不算在内、洞默认填掉、
  `courtyard:true` 保留院子、引擎炸了退回凸包、两栋楼两块地块、骨架每笔都在轮廓内且离边 ≥10%
- 用例 `test_177` **3/3**、`test_36`（AreaMap）6/6、`test_37` 5/5 未回归
- 样图 `build/building-symbol/preview.png` 扩到八格（四坡/双坡/长屋/平顶/L 形×2/带内墙三居/合院）
- 包 `sitian-setup-0.5.17.exe`
