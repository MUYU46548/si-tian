# 司天 · 顶层重排与施工顺序（2026-10-20 定）

**这是什么**：对《司天-中长期施工计划 v1.2》《M1 施工细单 v1》的**取舍结论**。不是又一份总纲 ——
总纲仍是云侧 v1.2；本文只回答一个问题：**先做什么、不做什么、为什么**。

**不是什么**：不排期（所有"周/月/人日"数字一律不作数）；不替代云侧细单里的技术设计。

---

## 一、顶层结构（修正 v1.2 的"四个工作区"）

```
宇宙与星系  ── 世界 → 星域 → 星系 → 恒星/行星（2D/3D 是这一块里的视图，不是独立模块）
行星与细节  ── 行星表面 → 区域 → 室内（省 / 河 / 地形 / 文化 / 宗教 / 道路 / 建筑内部）
历史剧本    ── 卡片墙 / 时间轴 / 势力 / 归属 / 外交 / 事件 / 切片 / 动画（最独立的一块）
        ↑ 三者共用同一份 Entity / MapDoc / Scenario / SpaceDoc
资料层（Obsidian）── 不是第四个模块，是横向能力：三块都能引用，但不占主入口
```

- 旧分法（设定库 / 地图 / 剧本 / 星图）错在两点：**星图属于模块一**、**设定库是资料层**。
- 历史剧本一直"格格不入"的根因：它被当成盖在世界选择页上的**遮罩**（`scenarioMode` + `z-index` 那一套），
  而不是一个**平级入口**。卡片墙修好后这一点更明显 —— 结构问题，不是像素问题。

## 二、三个选择（这一轮真正要定的事）

### 选择 1：**不重写账本引擎** —— 它已经存在

M1 细单把"自研事件账本"当成最大工程量。代码实况：

| 账本该有的 | 仓库里已有的 |
|---|---|
| 事件流 | `scenario.changeEvents[provinceId] = [{ y, m, d, owner }]`（`store/geodataModules/scenarioEditing.js`） |
| 任意时刻回放 | `buildTimeline()` + `currentOwnerRef(tl, k, pid, atDate)`（`utils/scenarioTimeline.js`） |
| 快照/基线 | `scenario.ownership` 就是该剧本结束时刻的压平快照 |
| undo | `store/undo.js` 的 `execute()`（一笔一命令） |

所以：**不新建 `src/ledger/`、不引入事件溯源库、不迁移 415 省数据**。
只补两件事：① 事件类型表（`province.owner.changed` 之外，战争/条约/兴衰留给后面）；
② 回放索引（按 `day` 排序一次、按时间点二分），让拖时间轴不用全表扫。

### 选择 2：**先修"能不能用"，再谈"模块壳"**

用户实测排序（2026-10-19）：涂归属名不副实 > 卡顿 > 河流 > 模块结构。
结构重排会让界面好看，但**不会让任何一件现在做不到的事变得做得到**。
所以顺序是：日常编辑可用 → 河流可信 → 模块壳（三入口）。

### 选择 3：**河流只留一条实现**

导入河（裸折线描边）、自动河（逐段描边）、手画河（曲线+变宽）此前是**三套画法**，
用户看到的"铁轨/竹节"就是逐段描边的接头。现在统一成：**一条闭合多边形（左岸+右岸）一次 fill**。
判据不是"看着像"，而是单测里 `fill ×1 / stroke ×1 / beginPath ×1`。

## 三、这一轮已经落地的（有代码、有用例、有真机截图）

1. **「涂归属」= 只改势力归属**（新工具 `ownerBrush`）：
   - 选势力 → 按住涂 → 笔刷碰到的省一次性 `batchSetOwnership`（**一条 undo**）；
   - **不碰多边形**：省界逐字节不变（用例 131 断言）；
   - Alt+点 = 吸管（取该省当前势力）；
   - 旧的几何笔刷改名 **「改省界」**，移进「底图编辑」行 —— 日常行不再有两个同名按钮。
2. **河流丝带**：`variableRibbon` / `fillRiverRibbon`（`utils/riverRender.js`），
   导入河 / 自动河 / 手画河全部走它；`widthFactors` 现在真的到画布（以前只传头尾两个宽度）。
   自动河生成 + 绘制从 ~317ms 降到 ~171ms（用例 103 实测）。
3. 用例 131（真实鼠标输入）、单测 `test_river_ribbon.js`、三处旧断言按新语义收紧。

## 六、2026-10-20 下午真机取证（真实 415 省项目副本）

三件事都不是"画法"问题，是**数据/热路径**问题：

1. **卡顿的真身**：`batchSetOwnership` 里 `JSON.parse(JSON.stringify(changeEvents))` 整表深拷
   + `saveScenarios()` 同步 `syncCanvasToProject`（导出并合并整份画布载荷）。实测一次 166ms。
   改成浅拷贝 + 300ms 合并保存后 **0.8ms**；单帧 render 20ms。
2. **河流宽度的真身**：真实数据 160 条河的 `width` 只有 0.03~0.26，旧公式算出 0.29px，
   全被 0.7px 地板夹住 —— **每条河都是发丝**，再压一圈深色岸线就是"两条边夹一条缝"。
   现在按本幅图 width 分布归一化到 1.2~4.6px，岸线归零，折线先过中点二次曲线圆角。
3. **"涂归属什么都涂不了"的真身**：没选势力时静默不干活（截图里就是"当前势力：未选"）。
   现在没选势力会自动落到本剧本第一个势力并回执；一笔划过 21 个省实测通过（一笔一条撤销）。

**副产品**：`历史剧本` 左栏的收起按钮只藏内容、留一个 236×全高空窗 —— 现在整块收成 40px。
