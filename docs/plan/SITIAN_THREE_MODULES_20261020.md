# 司天 · 顶层重排与施工顺序（2026-10-20 定）

**这是什么**：对《司天-中长期施工计划 v1.2》《M1 施工细单 v1》的**取舍结论**。不是又一份总纲 ——
总纲仍是云侧 v1.2；本文只回答一个问题：**先做什么、不做什么、为什么**。

**不是什么**：不排期（所有"周/月/人日"数字一律不作数）；不替代云侧细单里的技术设计。

---

## 一、顶层结构（修正 v1.2 的"四个工作区"）

```
宇宙与星系  ── 世界 → 星域 → 星系 → 恒星/行星（2D/3D 是这一块里的视图，不是独立模块）
行星与细节  ── 行星表面 → 区域 → 室内（省 / 河 / 地形 / 文化 / 宗教 / 道路 / 建筑内部）
历史剧本    ── 卡片墙 / 时间轴 / 势力 / 归属 / 外交 / 事件 / 切片 / 动画（最独立的一块）
        ↑ 三者共用同一份 Entity / MapDoc / Scenario / SpaceDoc
资料层（Obsidian）── 不是第四个模块，是横向能力：三块都能引用，但不占主入口
```

- 旧分法（设定库 / 地图 / 剧本 / 星图）错在两点：**星图属于模块一**、**设定库是资料层**。
- 历史剧本一直"格格不入"的根因：它被当成盖在世界选择页上的**遮罩**（`scenarioMode` + `z-index` 那一套），
  而不是一个**平级入口**。卡片墙修好后这一点更明显 —— 结构问题，不是像素问题。

## 二、三个选择（这一轮真正要定的事）

### 选择 1：**不重写账本引擎** —— 它已经存在

M1 细单把"自研事件账本"当成最大工程量。代码实况：

| 账本该有的 | 仓库里已有的 |
|---|---|
| 事件流 | `scenario.changeEvents[provinceId] = [{ y, m, d, owner }]`（`store/geodataModules/scenarioEditing.js`） |
| 任意时刻回放 | `buildTimeline()` + `currentOwnerRef(tl, k, pid, atDate)`（`utils/scenarioTimeline.js`） |
| 快照/基线 | `scenario.ownership` 就是该剧本结束时刻的压平快照 |
| undo | `store/undo.js` 的 `execute()`（一笔一命令） |

所以：**不新建 `src/ledger/`、不引入事件溯源库、不迁移 415 省数据**。
只补两件事：① 事件类型表（`province.owner.changed` 之外，战争/条约/兴衰留给后面）；
② 回放索引（按 `day` 排序一次、按时间点二分），让拖时间轴不用全表扫。

### 选择 2：**先修"能不能用"，再谈"模块壳"**

用户实测排序（2026-10-19）：涂归属名不副实 > 卡顿 > 河流 > 模块结构。
结构重排会让界面好看，但**不会让任何一件现在做不到的事变得做得到**。
所以顺序是：日常编辑可用 → 河流可信 → 模块壳（三入口）。

### 选择 3：**河流只留一条实现**

导入河（裸折线描边）、自动河（逐段描边）、手画河（曲线+变宽）此前是**三套画法**，
用户看到的"铁轨/竹节"就是逐段描边的接头。现在统一成：**一条闭合多边形（左岸+右岸）一次 fill**。
判据不是"看着像"，而是单测里 `fill ×1 / stroke ×1 / beginPath ×1`。

## 六、2026-10-20 下午真机取证（真实 415 省项目副本）

三件事都不是"画法"问题，是**数据/热路径**问题：

1. **卡顿的真身**：`batchSetOwnership` 里 `JSON.parse(JSON.stringify(changeEvents))` 整表深拷
   + `saveScenarios()` 同步 `syncCanvasToProject`（导出并合并整份画布载荷）。实测一次 166ms。
   改成浅拷贝 + 300ms 合并保存后 **0.8ms**；单帧 render 20ms。
2. **河流宽度的真身**：真实数据 160 条河的 `width` 只有 0.03~0.26，旧公式算出 0.29px，
   全被 0.7px 地板夹住 —— **每条河都是发丝**，再压一圈深色岸线就是"两条边夹一条缝"。
   现在按本幅图 width 分布归一化到 1.2~4.6px，岸线归零，折线先过中点二次曲线圆角。
3. **"涂归属什么都涂不了"的真身**：没选势力时静默不干活（截图里就是"当前势力：未选"）。
   现在没选势力会自动落到本剧本第一个势力并回执；一笔划过 21 个省实测通过（一笔一条撤销）。

**副产品**：`历史剧本` 左栏的收起按钮只藏内容、留一个 236×全高空窗 —— 现在整块收成 40px。

## 七、河流为什么会"空心"（2026-10-20 晚，结论）

不是宽度、不是颜色、不是岸线，是**多边形自交**：

- 上一版把左岸 + 右岸拼成一个闭合多边形再一次 `fill`。真实项目 30 条河 × 3 档宽度，
  **90/90 全部自交**（急弯处左右偏移互相穿过）；nonzero 填充在交叠区域抵消成洞 ——
  屏幕上就是"两条边夹一条缝"，放大后更明显（用户截图正是如此）。
- 现在的画法：中心线**分块描边**（默认 16 块/条，块中点取宽度、圆帽接缝）。
  结构上不可能有洞；160 条河 ≈ 2.5k 次 stroke/帧。判据写进单测：
  `stroke = chunks 次、fill = 0 次`。
- 圆角：中点二次曲线（不穿过控制点），90° 直角实测磨到 34°。

**仍未解决**：1× 下支流只有 1.2~2.5px，视觉上偏细（主因是数据 width 分布本身很窄，
已按分布归一化；要更粗就整调目标区间 1.2~4.6）。

## 八、2026-10-21：两项旧账收尾 + 大修切分

### 1. 省份「归属」可见性（已收尾，附真机验收）

问题：右键菜单与右上角详情都看不到归属；面板本身也不显示"这一年在谁手里"。

- **右键菜单**：新增「省份详情…」+ `归属：<势力名> / 无主（当前日期）`；势力色点与地图同源。
- **属性面板**：新增归属行（按 `tlDate` 显示），`清成无主` / `设为当前势力` 两个按钮都走 store
  （一条 undo + 写闸门；不在模板里直改活对象）。
- **口径**：`ownerPolityForProvince()` 与 `drawProvinces` / 势力标注共用 `polityLabelSources()`，
  不会出现「颜色是甲、名字写乙」。
- **证据**：`scripts/tests/diag_province_detail.py`（真机 + 真实项目工作副本）——
  菜单与面板都显示「瓯（前1350）」；点「清成无主」后 `ownership` 键消失、
  `changeEvents` 落下 `{y:-1350, owner:null}`，面板同步变「无主」。

⚠️ **语义纠正**：带日期的 `clearOwnership()` **会**写一条 `owner:null` 事件
（时间轴上就是「这一年这块地变成无主」）。旧交接里"清空会连带删掉易主事件"的说法已过时。

### 2. 河流「两条蓝线夹一条缝」（已收尾，附复核）

实测（真实项目工作副本，1×/2×/4×/8×/16× 截图 + 像素横截面）：现版本每条河都是**一条实心带**，
中场没有洞；对每条河的首块做 stroke 计数，可见的 18 条河**各只出现一次**（没有画两遍）。

10-20 那张「宽带 + 细深线」的截图无法在现版本复现。最可能的成因是分块圆帽在 α=0.95 下
**自己叠自己**（0.95 → 0.9975，把水色压出一道更深的细芯）—— 这也是"两条蓝线"里细的那条。

- **修法（结构性）**：河身**不透明**（α=1）。同色叠自己不改颜色，接缝不可能再压出第二种蓝；
  预览/草稿仍可显式传 `alpha`（如 0.85）。
- **单测**：`scripts/tests/unit/test_river_ribbon.js` 新增「默认不透明 / 显式 alpha 仍生效」。
- **复核工具**：`scripts/tests/diag_river_scan.py`（多档横截面）、`diag_river_dup.py`（重复描边计数）。

### 4. 河流「从某个节点开始变成双线」的真因（2026-10-21 晚，已修）

不是画法、不是接缝，是**导入数据本身就是往返路径**：

- 真实项目 **160/160** 条导入河都满足 `p[i] ≈ p[n-1-i]`（首尾相距 0.4~1.4 世界单位）。
  也就是说 `.map` 那条 `points` 存的是「源头 → 河口 → 原路回源头」的闭合路径，不是中心线。
  渲染时两程都画 → 从**折返点**（截图里的那个"节点"）开始出现两条平行线，中间夹着原河宽。
- 修法（显示期、不改用户数据）：`collapseReversedRiverPoints()` —— 后一半是前一半逆序重走时
  只保留 `[0..折返点]`；导入河的**显示列表与选中轮廓**都先折。
- 另加 `planRiverCoveredRuns()`：两条不同河共享同一段河身时（支流沿干流再走一遍），
  宽的先画、窄的跳过被盖住的连续段；横穿的支流由 ±45° 方向判据放过。
- 单测 8/8（往返折叠 / 绘制计划去重 / run 切分边界）；全量 **131/131**。
- 对照图（真实数据，同一视窗）：`docs/assets/diag-river-dedup-20261021/before-after.png`
  —— 左：原数据直接画（双线）；右：折成中心线后（单线）。

**模块壳补丁（同日）**：顶部栏在卡片墙上**常驻**（z-index 6000，卡片墙从 51px 下沿开始铺），
用户不再需要"退出卡片墙才能点世界观"；`test_129` 的旧判据（工具栏不在 DOM）改为

**顺序**：A（结构是地基）→ B（数据契约）→ C（性能/图层）。
**A 未收口之前不动 B/C 的代码** —— 上一轮的教训是"三个半截同时开"，最后只剩擦屁股。
