## 0. 结论先行

1. **运行时零 AI 依赖，是真的。** `src/`、`scripts/`、`package.json`、`package-lock.json` 里没有 AI SDK、没有 API key、没有 AI 端点；运行时没有一处 AI 调用。与 AI 有关的只剩：免责声明文案、一条注释、一个**没有任何写入方**的账本来源枚举 `PROVENANCE.AI='ai'`。
2. **核心功能不依赖 AI，也不依赖外部网络。** 本轮实跑 **146 个 Node 单测 + 8 个核心 CDP 用例**（地形 CRUD / 造陆 / 程序化河流 / 地形生成参数 / 剧本 JSON·SVG 导出 / PNG 导出 / 项目文件与快照 / 行星编辑），**8/8 通过**。应用启动不联网；只有“检查更新”和“Git 同步”两处联网，都是用户主动触发。
3. **真正危险的不是 AI，是交付状态。** 2026-11-26 已补做：27 个提交已 push（`b1d4803..142b2de`）、`v0.5.22` tag 已打并推送、GitHub Release v0.5.22 已发布（三件资产 uploaded、`latest.yml` 复核一致、Latest）。仍欠：0.5.23 的改动在 main 上但未发版（版本号仍 0.5.22）；架构图 `--check` 报 307 处不一致。
4. **“放弃读取设定库”不需要砍任何 AI 代码。** 那条线的产品实现本来就是确定性规则（frontmatter / 双链 / 路径 / 规则分类），AI 语义提取从未产品化。放弃它只会少一个“资料联动”功能，不会让核心功能变瘸。

### 3.2 砍掉 AI 会瘸什么

- **运行时：不瘸。** 产品里没有 AI 功能可砍。

- **维护面：会瘸的不是产品，是开发。** 零预算 = 没有 agent 继续改；冻结的安装包仍能跑。这是“零 AI 运行”与“零 AI 维护”的区别，别混。

- 更新检查、Git 同步：手动、可失败、不影响核心；离线可用。
