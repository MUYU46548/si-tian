# 司天 · 大规模重新调查计划（2026-11-04）

> 暮雨的原话：**“司天过于复杂，想要做好必须一开始就立好方向。我依然担心基座或框架出错
> （毕竟真的抄了很久，还是不像）。”**
>
> 这一页不是施工令，是**先量后改**的调查计划：每一阶段都有可证伪的判据，
> 量不出来就不许动手。结论要能回答两个问题：**“不像”到底像不像得起来**，以及
> **如果基座真的错了，错在哪一层**。

## 〇、先给结论（今天能证的三条）

1. **基座没坏**：Electron 28 / Vue 3 / Canvas 2D / 保存链 / 163 个回归用例 / 88 个 Node 单测
   今天全绿；`npm run build` 通过。没有发现“框架层错了”的证据。
2. **“不像”的第一因是数据尺度，不是算法**：真实 415 省孤本的底图是 **97×45 = 4,365 格**
   （格距 18.3 世界单位）；上游 FMG 默认约 **1 万个点**（格距 ≈3.5）。同一条河在 18 单位的格上
   只有 4 格长，在 3.5 单位的格上才有 20 格长 —— **河的“长度感/分叉尺度”被格距锁死**。
   证据：同一份地形，97×45 出 394 条（中位 4 格）；193×189 出 4,711 条（中位仍是 4 格）——
   条数随面积长，**河道长度按“格数”算，不按世界单位**。
3. **第二因是地形高频噪声**：我们的“造陆/推演”在格级造出大量局部极大，实测环岛地形上
   **18% 的陆格是源头**（FMG 的平滑 fBm 地形没有这个量级）。今天试过“路由前 3 遍箱式平滑”：
   源头数略降、结构不变 —— **治本只能靠提高格数或改造地形生成（侵蚀/夷平），不是调河网参数**。

## 一、P0 基座体检（半天，只读）

| 项 | 怎么量 | 通过标准 |
|---|---|---|

| 架构图 | `python scripts/gen_architecture_map.py` | 产物与代码一致，无“幽灵模块” |

> 基座有红的时候谈“像不像”是没有意义的。

## 二、P1 数据尺度审计（两天，只读实验）

**目的**：给“世界图最低格数”一个**数字**，而不是感觉。

做法：拿 415 省孤本的真实地形，**不改原文件**，在内存里重采样到 96 / 192 / 384 三档（各跑一遍
`buildRiverNetwork`），每次记录 6 个量：

1. 河的条数、中位格数、最长河（世界单位）；
2. 分叉密度（每万格的分叉点）；
3. 海岸线曲折度（周长²/面积，按省级轮廓）；
4. 等高线台阶（同一色带内“等高线间距 ≤2 格”的比例 —— 这是“地形糊/马赛克”的量化）；
5. 建网耗时；
6. 河网在 1×、1.5×、4× 三档缩放下的屏幕观感（各留一张截图）。

**通过标准**：三档都有表 + 截图落在 `build/scale-audit/`，并能回答一句
“**世界图在 N 格以上，河才读得出‘干流/支流’，再往上收益递减**”。

> 为什么必须先做这一条：今天的河引擎已经是**稳定的实现**（0 条孤段、每条河有身份/分级/湖），
> 再改算法也只是换一种“在 18 单位格上画 4 格长的河”的方式 —— 那是无效劳动。

## 三、P2 地形生成换挡（三天，会动数据，先备份）

按 P1 的结论，三件事按顺序做：

1. **默认格数换挡**（`terrainParams.cellsAcross` 的默认值）：改默认会推翻 0.4.0 的黄金哈希
   （`unit/test_terrain_params.js` 的 7/11/23 三个 sha256）——**这是有意的**，要同时重立黄金值，
   并在 AGENTS 里写清“旧值为什么作废”。
2. **加一层侵蚀**（今天完全没做）：FMG 的 `downcutRivers` 只下切河床；真正让地形“像真的”的是
   坡面侵蚀（D8 + 简化的水力侵蚀）。判据：同 seed 确定性、体积/面积守恒、
   最长主河变长（现在是 1,701 世界单位，量它）。
3. **湖从“格级水面”升级成“多边形湖面”**：现在 `hm.lakes` 只有 `{level, cells}`，
   渲染走格级双线性 → 边缘是虚的（截图 `build/pixel-baseline/v20261104a.png` 里能看见）。
   做法：沿用 `landmass.js` 的“抖动网格拓扑 + 按高度取几何”那一套，把湖格连成环。

**通过标准**：同一张地形在换挡前后各留一份底图；**415 省孤本先备份再动**；
像素基线重立并写进 AGENTS。

## 四、P3 “像不像”的对照实验（两天）

**目的**：把“不像”拆成**可以分别解决**的三类差异，而不是一句“还是不像”。

1. 装一份上游 FMG（离线 `index.html`），用**同一份高度图**（导成它的 JSON）跑一遍；
2. 司天与 FMG 用**同一取景、同一比例尺**各截一张（河/海岸/配色/文字/图例分开截）；
3. 逐项填表：`差异项 | 归因（数据 / 算法 / 表现） | 可执行动作 | 预估代价`。

已知会出现在表里的项（今天就能预判）：

| 差异 | 归因 | 备注 |
|---|---|---|
| 河网尺度/分叉密度 | 数据（格距 5 倍） | P1/P2 解决 |
| 河“手绘感” | 算法（已抄 meander + relaxAcuteAngles，但格距粗时看不出来） | 换挡后复看 |
| 海岸线“死清” | 表现（3px 岸线 + 0.18 光带，已经降过一档） | 与地形档的强弱关系 |
| 地形“糊 / 马赛克” | 表现（格级填色 + 双线性上采样） | 等高线已缓解，根因仍是格数 |
| 图例/比例尺/指北针 | 表现（**根本没有**） | 地图的“专业感”一半来自这里 |
| 城市/道路/国界的层级 | 算法 | 目前只有省界一档 |

## 五、这一轮明确**不做**的事（以及为什么）

- **外交可写**（反馈 #7）：它和“地理像不像”是两条线。先不混进来，免得又把一件事做成半件。
- **UI 壳重排**（反馈 #6）：要在“能让用户连续画 7 天”的前提下才值得做；等地形换挡定稿。
- **编辑器侧的河名/改宽**：河引擎刚换成“每条河有 id/parent/basin/order”，**现在才第一次有地方挂名字**；
  等 P1 的格数定了再接（否则要为两套几何各写一遍）。

## 六、风险与止损

1. **换格数会动用户数据** → 415 省孤本施工前后各留底（SHA256 一致），并提供
   “旧底图 / 新底图并存”的开关，不给用户“只能重来”。
2. **侵蚀层可能让地形变丑** → 侵蚀必须能整体关掉（一个参数回 0），并把开/关两帧都进像素基线。
3. **调查阶段不许顺手改产品** → P0/P1 只读；一旦发现缺陷，**登记成卡**，不在这两阶段里修。
4. **“像”没有终点** → 每一阶段结束时，只认“判据过了”，不认“我觉得像了”。
