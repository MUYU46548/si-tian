# 一、先答这 5 题

## ★S1 这东西最终给谁用？
- **A. 只给我自己**（写小说 / 设定集）
- **B. 我 + 少数同好**（能分享项目文件、别人能打开）
- **C. 以后对外发布**（安装包 / 文档 / 陌生人能上手）

【现状】只有一个用户（你）；项目文件是单人本地文件，无账号、无协作、无分享机制。
【默认】**A**（先把自己这条路走通，不花时间做上手文档）
【验收线】选 B/C 才做“别人拿到能打开”的示例项目 + 三条最小说明；选 A 一律不做。

## ★S2 最终要交出去的“成品”是什么？（可多选，按重要性排）
- **A. 一张能发出去的图**（B站/插图/封面）
- **B. 一套可查的设定库**（地理 / 势力 / 年表都能翻）
- **C. 一段可播放的演变**（时间轴回放 / 切片成视频）

【现状】A 有：整图 PNG、切片 PNG/SVG 导出，且导出的 SVG 与画布同一套画法（用例 `test_100`）。
B 有一半：剧本/事件账本/势力归属都能存能查，但没有“设定集视图”（人物、地理、年表放一起翻）。
C 有一半：时间轴与逐代切片在，**没有视频导出**。
【默认】**A > B > C**（先把图做对，再补设定集，视频不进首版）
【验收线】每条链路都要有“从项目到成品”的验收（不是“功能存在”就算），成品文件本身要能被你直接拿去用。

## ★S9 判“像不像”的标准到底是什么？
原卷问“像现成品算不算问题”，但你今天的原话是“**抄了很久，还是不像**”——所以真问题不是“要不要像某家”，
而是“**像到什么程度算过关**”。
- **A. 像真实地图**（地理逻辑对：河从山到海、海岸是碎的、坡面有谷）
- **B. 像某个产品**（FMG / Azgaar 的观感）
- **C. 有自家风格**（不追写实，只要一致好看）

【现状】河引擎今天已按 FMG 真实源码重抄（`utils/fmg/rivers.js`）：孤段 0、每条河有分级/流域/湖、
降水决定密度。**但观感仍受格距限制**：真实底图 97×45，河的中位长度只有 4 格；256 格时约 11 格。
差距已定位到“格距 + 地形没有侵蚀”，不是算法。
【默认】**A**（像真实地图）；B 不作为判据 —— 我们的目标不是复制某家的配色。
【验收线】选 A 的判据是**几何指标**（中位河长 / 分叉密度 / 海岸曲折度 / 等高线台阶），不是“我觉得像了”。

## ★S17 AI 该不该参与？（方寸从没问过这条，但它是最大的一条）
- **A. 不要**——司天就是编辑器，数据全是你手写
- **B. 只给建议**——命名、史料草稿、势力关系草稿，**你点了才写入**
- **C. 可以直接写**——AI 能落库（走撤销）

【现状】**没有任何 AI 入口**；项目数据全是本地手写、可撤销。
【默认】**B**（只建议，不落库）
【验收线】选 B/C 必须同时有：① 产出可一键撤销；② 条目上标“AI 生成”；③ 不许静默改已有数据。

## ★S19 示例行星要不要重新生成一版底图？
- **A. 先不动，等 P1 审计给数**
- **B. 现在就出一版 256 格**（更细，但会动 415 省孤本）
- **C. 出新的，旧底图并存**

【现状】真实孤本底图 **97×45（格距 18.3）**；生成器的网格精度可选 64/96/128/160/192/256（默认 192），
256 格跨示例行星图幅约 **3 万格（格距 ≈6.9）**，河的中位长度能从 4 格拉到 ≈11 格；
但**生成器现在没有侵蚀**，所以“扭曲的规整”不会因为换格数而消失（今天截图里能看到优先洪泛留下的平行排水纹）。
【默认】**A**
【验收线】重生成前必须交三个数：① 256 格下河网是否还像电路板（截图 + 中位格数）；② 规整感是不是来自
洪泛台阶（开/关路由平滑对照）；③ 代价（耗时 / 底图体积 / 要不要重切省）。三个数齐了再动孤本。

## ★S20 首版“能开始用”的最小范围（7 天验证）
- **A. 一条链路**：建世界 → 造陆 → 切省 → 涂归属 → 导出图
- **B. 两条**：上面 + 剧本时间轴 / 切片
- **C. 三条**：再加 保存 / 备份 / 只读闸门

【现状】三条**功能上都已经存在**且有回归用例；缺的是**串成一条不别扭的流程** —— 入口散在 55 个按钮里，

【默认】**B**
【验收线】7 天内不看手册走完全程；卡住的地方记成卡，**不现场加功能**。

# 二、原 9 题（前提已按现状改写）

## S8 模拟深度
- **A. 不搞模拟**（纯编辑器）
- **B. 轻模拟**（一键分析 / 派生，不推演过程）

【现状】**已经是 B**：气候派生（温度/降水/群系）、文化/宗教/势力派生、剧本按年回放归属；
**没有**战争推演。C 没有任何基础设施（没有行动体、没有回合、没有冲突解算）。
【默认】**B**（保持现状，不加推演）
【验收线】首版不引入“结果不可预知”的推演；新增派生必须可一键重算、可撤销、有确定性 seed。

## S10 笔刷体系（原题前提过期）
原选项把“全笔刷栈”当要不要做，其实**已经有了**：高度/地形、湖、群系、文化、宗教、省界、涂归属、
手画河，共 8 类；**唯一没有的是侵蚀笔刷**（把坡面刷出被水冲过的沟壑）。
- **A. 加侵蚀笔刷**
- **B. 不加，现有够**
- **C. 先不做，等地形生成换挡**

【现状】8 类笔刷在跑；手改可被“重生成”保住（`handEdits`，按世界坐标登记）；**无侵蚀笔刷**。
【默认】**C**（先换地形生成，再决定要不要手刷侵蚀 —— 否则就是给一张要被替换的地形做笔刷）
【验收线】选 A 必须：可撤销、415 省上一笔 ≤50ms、重生成后手刷痕迹不丢。

## S11 导入导出
- **A. 现在够**（图进图出 + `.map` 导入）
- **B. 加高度图互导**（和 WorldPainter / Terrain Studio 通）
- **C. 加 GeoJSON**（和 GIS / 别的地图工具通）

【现状】已有：`.map`（Azgaar）导入（含逐省对拍）、整图 PNG、切片 PNG/SVG、参考图导入；
**没有**高度图导出、**没有** GeoJSON。
【默认】**A**
【验收线】新增格式必须有“读回对拍”用例（导入 → 导出 → 再导入，逐字段一致），否则不做。

## S12 旧司天处置（原选项前提已经不成立）
原卷写“A 全推倒重来 / B 保逻辑拆壳（**6920 行 UI 壳**重做）”。这两个前提都过期了：
引擎/数据层有 163 个用例护着；UI 也不是一个 6,920 行的文件 —— 现在是 **57 个组件 / 25 个异步面板**，
最大的 `ScenarioMap.vue` 6,942 行（样式已外链）。
- **A. 保引擎/数据层，只重做界面**（现行计划）
- **B. 连引擎一起重写**
- **C. 先不动界面，只补功能**

【现状】AGENTS 的现行规划就是 A（“保留引擎、只重做壳、先 7 天最小验证”）。
【默认】**A**
【验收线】选 B 必须先给出“引擎哪里错了”的证据 —— 目前一条都没有（今天反而把河引擎按上游源码重抄通了）。

## S13 画布层级（原题前提已过期）
原题问“世界级单层 vs 多层级下钻”，但**七层已经在跑**（world → domain → system → system_detail → planet
→ area → interior）。真问题是：**剧本底图要不要分幅**。
- **A. 一张世界图**（现状）
- **B. 世界图 + 重点区域详图**（两张，可互跳）
- **C. 世界图 + 任意区域裁切放大**（同一份数据，裁剪视图）

【现状】剧本底图是一张（可以有多张底图切换，但那是“不同世界/不同图”，不是同一世界的分幅）。
【默认】**C**（同一份数据的裁剪视图，成本最低、不会出现两套真值）
【验收线】B/C 都必须“坐标可回写”（区域图上改的东西要能回到世界图），否则不做。

## S14 视觉标准
- **A. 地理课本风**（分层设色 + 山体阴影 + 等高线）
- **B. 政区色块风**（干净，适合演变回放）
- **C. 手绘内页风**
- **D. 先不管好看**

【现状】A 的大部分在跑：分层设色、浮雕阴影、等高线、政治水洗、三级线宽；今天刚重立像素基线
`v20261104a`。B 有“政治档”但不是一套完整样式。**C 完全没做**（没有任何手绘笔触/纸纹）。
【默认】**A 继续做深，B 作为“演变模式”的第二套样式，C 进 backlog**
【验收线】改默认样式必须重立像素基线并在 AGENTS 写新 tag；C 若要做，先出一张样图再谈工程量。

## S15 手感对标
- **A. WorldPainter 手感**（桌面手绘，像 PS 一样刷）
- **B. Terrain Studio 手感**（网页 GPU 笔刷，“鼠标划过就有”）
- **C. 都不是**（改一句说感觉）

【现状】原生 Canvas 2D，**没有 GPU**；笔刷/拖动/撤销/帧合并都有；415 省整帧渲染中位 **10.9ms**，
但“涂归属一笔”的松手同步段 **62ms**（目标 ≤50ms，未达标）。
【默认】**A**（桌面临场感），但把 B 的“划过就有”当**笔刷延迟目标**
【验收线】选定后 UI 单挂此锚；**笔刷/落笔延迟 ≤50ms 是硬指标**，达不到不许加新功能。

## S16 生成 vs 手画的比例
- **A. 生成打底 + 手画微调**
- **B. 手画为主**
- **C. 各半**（地形生成、区划/历史手画）

【现状】两条都在：造陆 / 按轮廓推演 / FMG 模板（14 套）+ 手画省/河/地形 + 手改可保留。
【默认】**C**（地形生成，区划与历史手画）
【验收线】默认流程必须能“一键出地形 → 手改 → 再生成**不覆盖**手改”，这条已有用例守着。

【现状】手册与截图里目前用的是“像素甲国”这类占位名；**没有发布前的隐私扫描流程**。
【默认】**B**（名字与长相都不进；素材一律自造）
【验收线】发布前跑一遍隐私扫描（源码 / 文档 / 示例 / 截图里 grep 私人专名），并带一条负向探针。

## S28 崩溃与反馈
- **A. 不要任何上报**
- **B. 本地日志一键导出**（用户自己发给你）
- **C. 可选匿名统计**

【现状】无遥测；错误显示在画布横幅与状态栏，用户拿不到可发的文件。
【默认】**B**
【验收线】选 B 要有一个“导出诊断包”入口，且包里含什么写在按钮说明里。

## ★S29 项目文件格式的兼容承诺
- **A. 从现在起不破坏旧项目**（新字段可加、旧语义不改；破坏性改动必须带迁移器）
- **B. 发布前随便改**，发布后才承诺
- **C. 只保证 1.0 之后**

【现状】`.sitian` 在 0.5.x 期间改过几轮（剧本集 / 账本 v2 / 湖泊字段），有迁移脚本，但**没有版本闸门**。
【默认】**A**
【验收线】每个格式改动都要有一条“上一个发布版的项目能打开”的用例。
