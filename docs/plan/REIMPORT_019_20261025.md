# 019 底图重导：语义与设计（2026-10-25）

> 暮雨拍板：**换新 `.map` = 新底图 + 旧归属迁过去**。
> 「同一底图只补数据」只限这张底图**一笔都没改过**；只要动过一笔，它就和原底图不是一个东西。
> 本文是落地设计；纯函数已实现（`utils/basemapIdentity.js`），UI/写口尚未接。

## 1. 判定「一笔未改」：内容指纹，不用 updatedAt

- `basemapFingerprint(bm)`：规范 JSON（对象键排序）后哈希，覆盖
  `terrain` 几何 / `heightmap`（h/temp/prec/biome/culture/religion/grid）/
  `rivers` / `routes` / `burgs` / `referenceImages` / `landFeatures`。
- 导入/刷新时用 `stampBasemapSource(bm)` 把 `contentHash` 写进 `baseMap.source`。
- `isBasemapPristine(bm)`：当前指纹 == 导入时指纹。
- 旧项目没有 `contentHash` → **保守判「改过」**（走新底图迁移，绝不覆盖用户编辑）。
- 优点：不需要在几十个写口各插一行 `dirty = true`（漏一处就静默覆盖）；`updatedAt` 保存一次就变，不能用来判。

## 2. 两条路

### A. 一笔未改（pristine）

复用现有 **「刷新底图数据」**：只补缺（高度图/河流/道路/城镇），不动省份、不动归属、不换 key。
已有实现：`updateBaseMapData()`（B2，test_101/test_94 守）。

### B. 改过一笔（默认）

1. 解析新 `.map` → bundle（省份/高度/河流/道路/城镇）。
2. 新建底图 key：`<oldKey>__reimport_<YYYYMMDD-HHmmss>`；name = `<oldName>（重导 YYYY-MM-DD）`。
   - 同 key 绝不覆盖（否则旧底图与旧剧本的退路就没了）。
   - `stampBasemapSource(newBm)` 盖新指纹。
3. 旧省→新省映射（`mapProvinces(old.terrain, new.terrain)`）：
   - **id 完全相同**优先；
   - 否则「新省形心落在旧省」；
   - 再否则「旧省形心落在新省」。
   - 拆省（一旧对多新）→ 旧归属复制到每个新省（不算冲突）。
   - 并省（多旧对一新）→ **冲突清单**，默认**阻止迁移**（不替用户选），列出「新省 ← 哪些旧省」。
   - 未映射的旧省 → 清单；未映射的新省 → 清单（新长出来的地，无主）。
4. 迁移（只动 `ownerKey === oldKey` 的剧本）：
   - `scenario.ownerKey = newKey`；**scenario.id 保持不变**（避免断掉外部引用；`getScenariosByOwner` 看 ownerKey）。
   - `ownership`：旧 pid 的 owner → 所有映射到的新 pid；冲突则阻止。
   - `changeEvents`：同上逐条复制（一旧对多新 = 每条事件复制到每个新省）。
   - `initialOwnership`（账本 v2 字段）同样重映射。
   - `labels` / `markers`：坐标原样保留（世界坐标；新图范围不同时由用户再调，不静默缩放）。
   - `groups` / `slicePoints`：不动（项目级）。
   - `timelineEvents`：不动（按势力，不按省）。
5. 旧底图：保留，`archived: true`，从底图下拉里标「（旧）」；其剧本已全部迁走。
6. 参考图：**默认不随迁**（新 `.map` 有自己的地理；用户可在对话框勾选「带上旧参考图」）。
7. undo：整次迁移 = **一条 undo**（快照旧 baseMaps + scenarios，redo 写新状态）；旧底图始终保留。

## 3. 冲突与回执

- 有并省冲突 → 不写任何数据，弹「冲突清单」：`新省 X ← 旧省 A、B（面积 ...）`；用户可取消，或后续加「按面积大者」。
- 有未映射旧省 → 允许继续，但清单必须可见（这些省的归属会丢）。
- 完成后状态栏：`已重导为新底图「…」：迁 N 条剧本 / M 个省归属 / 冲突 0`。

## 4. 入口

- 在「底图」组里加一颗「重导为新底图…」（或复用导入按钮：选文件后先判 pristine，
  pristine → 问「只补数据 / 新底图迁移」；改过 → 直接走迁移并说明）。
- 对话框显示：旧底图、新文件、省份数变化、映射统计、冲突/未映射清单、是否带参考图。
- 只读态灰禁（走 `guardWrite`）。

## 6. 验收

1. 一笔未改的底图重导 → key/ownerKey 不变，只补缺（旧行为）。
2. 改一笔的底图重导 → 新 key、旧底图归档、归属/易主/剧本集/切片点完整；旧底图可回退。
3. 并省冲突 → 零写入 + 可读冲突清单。
4. 一条 undo 全还原。
5. 415 省真实项目上跑一次（副本），不丢任何剧本/归属。
